# ADR-0003：插件以 pi package 形式组织和分发

- **状态**：已接受
- **日期**：2026-09-29
- **相关**：[ADR-0001](0001-use-pi-as-core.md)、[ADR-0002](0002-connect-pi-via-rpc-subprocess.md)

## 背景

插件既要有逻辑（在 agent loop 里注册工具、处理钩子），又要有桌面端界面。由于 RPC 模式不转发自定义 UI，两部分运行在不同进程里。同时希望插件将来可以分享。

## 决策

一个插件 = pi extension（逻辑）+ 桌面视图（渲染），打包在同一个 pi package 里。视图入口声明在 `package.json` 的 `atrium` 字段中，pi 会忽略该字段。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 自建插件格式和分发 | 完全可控 | 安装、版本、分发都要自己做 |
| 逻辑和视图分成两个包 | 职责清晰 | 版本要手动对齐，安装两次 |
| 同一个 pi package（采用） | 一次安装；直接复用 `pi install` 和 package gallery | 视图部分依赖自定义字段，脱离 Atrium 时会被忽略 |

## 后果

- 正面：分享能力几乎免费获得；插件逻辑在纯 pi 环境下也能工作。
- 负面：插件视图只在 Atrium 里可见。
- 重新评估：若 UI 扩展需要跨宿主复用，考虑向 MCP Apps 等标准靠拢。
