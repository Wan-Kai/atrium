# ADR-0002：通过 RPC 子进程接入 pi

- **状态**：已接受
- **日期**：2026-09-29
- **相关**：[ADR-0001](0001-use-pi-as-core.md)

## 背景

pi 提供两种嵌入方式：进程内 SDK（`createAgentSession()`）和 RPC 模式（子进程，stdio 上的 JSONL）。

## 决策

以子进程方式运行 `pi --mode rpc`，每个会话一个进程，由 harness 适配器负责启动、监督和翻译事件。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 进程内 SDK | 调用直接，类型完整，延迟低 | pi 或插件崩溃会拖垮桌面端；多会话隔离差 |
| RPC 子进程（采用） | 进程隔离；与 Paseo 等项目做法一致；适配器形态可复用到其他 harness | 需要处理进程生命周期；协议层多一次序列化 |

## 后果

- 正面：崩溃隔离，多会话互不影响；适配器天然就是接入其他 harness 的样板。
- 负面：RPC 模式只转发对话框和通知，不转发自定义终端 UI，插件视图必须由桌面端自己渲染（见 [插件模型](../architecture/plugin-model.md)）。
