# ADR-0007：每个对话是一个独立的容器

- **状态**：已接受；第 1 条里"以后浏览器页面也作为对话里的标签页"已取代（被 [ADR-0009](0009-browser-stays-external.md) 取代）
- **日期**：2026-10-12
- **相关**：取代 [ADR-0006](0006-organize-sessions-by-workspace.md) 第 4 条；[SPEC-0001](../specs/0001-mvp1-single-session-chat.md)"侧栏 · 对话"、[领域模型](../architecture/domain-model.md) §1

## 背景

ADR-0006 第 4 条把不绑定工作区的"对话"放进一个全局的容器（ChatSpace）：侧栏"对话"分区列的是会话，选中"对话"时，所有打开着的对话都是同一个标签栏里的标签页。

自用（M1.11）时发现这样不对：一个对话其实是一个没有 git 的工作空间，有它自己的目录，以后还会有要打开的浏览器页面等内容；把所有对话挤在一个标签栏里，彼此的内容混在一起，切换也乱。

约束：

- pi 必须有工作目录，每个对话已经有自己的目录 `~/.atrium/chats/<dirId>/`，宿主按目录认出它们（ADR-0006）。
- 对话内容只在 pi 的会话文件里，Atrium 只存索引。
- 已经在用的数据（`sessions.json`、`layouts.json` 里的 `chats`）要能无损迁移。

## 决策

**每个对话是一个和工作区并列的容器（Chat），一个目录一个对话，只是没有 git。**

1. **对话里可以有多个会话**，和工作区一样：标签栏的"+"（⌘T）在这个对话的目录里新建会话，"历史"列出这个对话的会话。⌘N 和侧栏的"新建对话"新建一个对话。以后浏览器页面也作为对话里的标签页。
2. **对话的 id 由目录名得出**：`cht_<目录名>`。目录是 Atrium 自己建的、名字随机，所以 id 稳定；终端里在对话目录开的 pi 会话按 `cwd` 自动归到这个对话。
3. **侧栏像工作区一样逐行列出对话**：名称、最近活动时间、会话的最高优先级状态。显示最近 5 个，更多的点"显示全部 N 个"在原地展开。所有会话都归档了的对话不再列出。
4. **名称**：取第一个会话的标题，可以重命名；自定义名称存在索引（`chats.json`）里，清空即恢复默认，和工作区的自定义名称一样。
5. **不再有全局的 `chats` 容器**。旧的索引按会话的工作目录迁移到各自的对话，打开着的标签页跟着会话走。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 保持全局 ChatSpace（ADR-0006 第 4 条） | 不用改 | 所有对话挤在一个标签栏，以后对话里的浏览器页面等内容无处安放 |
| 一个对话只有一个会话，不要标签栏 | 简单 | 对话里想换个话题或并行问第二件事时只能再开一个对话，目录里的文件看不到；和工作区不一致 |
| 对话是"没有 git 的工作区"，挂在一个虚拟项目下 | 复用工作区的全部代码 | 工作区和项目、git、合并状态绑得很紧，硬塞会让工作区的规则到处要加例外 |
| 对话是独立的容器，能放多个会话（采用） | 和工作区的使用方式一致；以后能放浏览器页面；迁移只看目录 | 多一种实体，协议、索引都要改；要迁移已有数据 |

## 后果

- 正面：对话之间互不干扰；工作区和对话的切换、标签栏、"历史"、空状态是同一套交互；以后对话里的其他内容（浏览器页面）有自然的位置。
- 负面 / 代价：
  - 协议版本加一：会话的 `containerId` 是工作区或对话的 id；新增 `Chat` 实体、`rename_chat`；`create_session` 也能在对话里新建；`list_models` 改成按工作区，不在工作区里的（所有对话和设置）共用 Atrium 目录的列表。
  - 索引新增 `chats.json`（自定义名称），`sessions.json`、`layouts.json` 升到 v2，迁移时备份旧文件。
  - 侧栏的"对话"分区以前点一行就打开那个会话，现在点的是对话：没有打开着的标签页时打开它最近的会话。
- 什么情况下应重新评估：要把对话"移到项目"时；对话需要 git 时（那它就该是工作区）；对话的数量多到侧栏放不下、需要分组时。
