## 独立审查结论

### Astra

- Standards：无确定发现。
- Spec：1 中——正式宿主发送 `pair_rejected.reason = rejected`，Swift 只把 `declined` 识别为 Mac 拒绝；手机因此显示通用连接失败。没有错误授予权限。

### Grok 4.7

- Standards：无确定发现。
- Spec：1 中、2 低——本次活性探测超时主动断开正常控制 / 手机连接；切设置分类后侧栏提醒丢失；配对确认弹层未标注型号由手机自报。
- 父会话核对后限定第一项：**仅探测超时不应主动踢手机**；relay 真正关闭、4401、正常心跳判死时，原有断链仍正确，不能为了“不打扰”忽略真实失联或拒绝。

### Claude Opus 5.5

首次因认证 403 中断，不计为完成；恢复后完成同一冻结范围的独立只读审查，并做一轮限定澄清。

- Spec：修订后保留 Mac 拒绝原因、侧栏提醒，以及 iOS SDK 返回通用设备名称这一平台 / 设计限制。
- Standards：保留“撤销写盘失败后，做其它操作会覆盖唯一重试入口”。这是可达的功能恢复问题，不是纯样式问题。
- 撤回为代码缺陷：live + 4401 的 token 步骤仍为 unknown。它表达本次没重测认证，明确拒绝另在 failure；维持已批准的 connect/live 区分，待补精确说明与边界验证。
- 撤回为当前生产可达缺陷：手机名字超过 64 个 UTF-16 单位。当前 iOS 26 接线没有设备自定义名称 entitlement，SDK 声明返回通用型号；任意调用方输入仍属潜在边界，不为未来接线预置功能。
- 降为观察：保险箱写入等待可能拖住宿主关闭，触发 5 秒强杀；没有违反现有明确契约。不能将读不会阻塞关闭扩称写入也有相同保证。
- 保留存疑：保险箱解密 reject 被统一映射为 corrupt；平台授权拒绝是否也走这一路尚无实测，不能凭假 crypto 的行为断言真实钥匙串结果。正在只读核查 API 证据，不操作用户现有钥匙串或保险箱。

## 修复与决定

| 项目 | 当前处置 | 验证边界 |
|---|---|---|
| Mac 拒绝原因 | 手机分支 `1399b0c`：生产映射增加 rejected，保留 declined 与未知原因兜底 | 作者报告窄 Swift 11 项、破坏 1/1；正式 RemoteService → Swift 动态拒绝回归另行实现，尚不等于通过 |
| 探测超时踢手机 | 宿主分支 `c4620ef`：不 terminate，不把单次 probe 失败置为生命周期 error | 作者报告真实 socket 单元 39、真实 relay / Noise 宿主 64、破坏 22/22；新源码增量变异尚未跑 |
| 型号自报说明 | UI 分支 `cc61b01`：确认弹层明确自报 / 非硬件认证，空白型号为未提供 | 作者报告 3 红 → 3 绿，破坏 3/3 |
| 侧栏提醒 | **用户明确选择：整个 Mac 设置窗口持有订阅**。切分类不退订；真正关闭窗口退订、清空页面状态。不全局常驻，不改变手机连接或配对权限 | UI 分支实施中；设置未保存配置拦截关闭时，仍保持订阅 |
| 撤销重试入口 | 父会话已核实 `run()` 清除唯一 failure，设备又被宿主隐藏，导致其它操作后无法重试原撤销 | 待最窄回归与修复，不新增持久离线队列 |
| 名字 / 型号为通用 iPhone | SDK 头文件为静态证据；尚未真机测值。先保留限制，不擅自加手机命名页或硬件型号词典 | 既有 Mac 改名能力不变；不声称能读到用户给 iPhone 起的名字 |
