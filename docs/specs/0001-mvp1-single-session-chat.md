# SPEC-0001：MVP 1 单会话对话

- **状态**：评审中
- **创建**：2026-09-30
- **更新**：2026-10-01
- **相关**：[路线图](../roadmap.md) 阶段 1 第 1 步、[ADR-0002](../adr/0002-connect-pi-via-rpc-subprocess.md)、[ADR-0005](../adr/0005-split-host-and-ui-pwa-first.md)、[事件模型](../architecture/event-model.md)

## 背景与目标

Atrium 的第一个可用版本。它要回答一个问题：**在 Atrium 里用 pi 加 Codex 模型，能不能完成日常的真实编码任务？** 如果不能，整条路线都要调整，所以越早知道越好。

同时，它会把 ADR-0005 定下的架构从头到尾打通一遍：Electron → UI → WebSocket → 宿主 → pi RPC。后面的 MVP 都在这个骨架上叠加。

完成后：你可以在 Atrium 里打开一个项目、和 pi 对话写代码，并且能看清它做了什么。

## 非目标

- Atrium 自己的 extension：审批、上下文检查器都放到 MVP 2。但用户自己安装的 pi extension 弹出的对话框必须能显示和回答（需求 10），否则会话会卡住
- 审批：沿用 pi 的默认行为，工具调用直接执行
- 同时运行多个会话、worktree
- 浏览器操作的专门界面（通过 pi 的 `mcp.json` 配置 MCP server 即可使用）
- 插件系统、会话树、分叉
- 打包、签名、自动更新；手机端和 PWA；多窗口
- 文件系统相关：审查面板、文件路径操作（用编辑器打开、在 Finder 中显示等）
- 系统通知
- 订阅额度（5 小时、每周用量）：不在对话面板里显示

## 需求

1. 当我打开 Atrium，我希望在侧栏看到各个项目和其下的工作区（本地目录或 worktree），一眼看出哪些在运行、哪些在等我处理、哪些 worktree 还没合并；在对话区顶部用标签页切换同一工作区里的会话（见下文"侧栏""对话区"）。
2. 当我新建会话并输入需求，我希望看到流式输出的回复和推理过程。
3. 当我粘贴或拖入一张截图，我希望它随消息一起发给模型。
4. 当 agent 调用工具，我希望看到它做了什么：执行的命令和输出、读了哪个文件、改动的 diff、新写入的文件。
5. 当 agent 走偏了，我希望随时中断它。
6. 当 agent 还在运行时，我希望继续输入的消息默认排队；需要时点一下，就能让它在 agent 下一步之前送达（插话）。
7. 当我想换模型或调整推理强度，我希望在输入框旁边直接切换。
8. 当我关掉 Atrium 再打开，我希望恢复之前的会话继续聊。
9. 我希望在输入框下方的状态栏随时看到上下文用量、缓存命中率、token 用量、输出速度，并能选择显示哪些指标。
10. 当我自己安装的 pi extension 弹出对话框提问时，我希望在 Atrium 里看到并回答它。
11. 我希望对话默认只突出回复，过程折叠起来；需要时能切换显示模式，查看推理过程或每一步的细节。
12. 我希望能复制一条消息，或者复制一整轮对话。

## 方案设计

### 进程与启动

```
Electron 主进程
  ├── 启动宿主（Node 子进程），生成随机 token，宿主监听 127.0.0.1 的随机端口
  └── 窗口加载宿主提供的 UI，并通过 preload 把地址和 token 交给 UI

宿主
  └── 当前打开的会话 → 一个 pi 子进程：pi --mode rpc [--session <文件>]，工作目录为项目目录
```

- MVP 1 同一时间只有一个活动会话。切换会话时关闭当前的 pi 进程；如果它还在运行，先提示中断。
- pi 进程意外退出时，宿主通知 UI，用户可以一键重新打开这个会话。

### 各包职责

| 包 | MVP 1 要做的 |
|---|---|
| `protocol` | 用 zod 定义下文的命令和事件 |
| `client` | WebSocket 连接（带 token、断线重连）、收发协议消息、维护会话状态：消息列表、流式拼接、运行状态、用量 |
| `host` | WebSocket 服务和鉴权；项目和会话列表；pi 适配器：启动和监督进程，把 pi 事件翻译成 Atrium 事件 |
| `ui` | 界面，见下文 |
| `apps/desktop` | 启动宿主、创建窗口、preload 传 token |

```

│ 收件箱        │                                          │
│ 项目 → 会话    │ 状态栏（输入框正下方，居中）                 │

```

- **视觉**：以 DeepSeek Harness 的产品界面为基准，逐个组件实测后对齐（系统字体、半透明侧栏与主区贴合、14px 常规字重为主、0.5px 细线、圆角 8 / 12 / 16 / 22）。
- **图标**：Phosphor Icons。14～18px 用 regular（屏幕线宽约 1px），20px 以上用 light；状态图标是纯线性图标，只给图标上色，不加底色。
- **动效**：以 Apple 为基准，用弹簧（时长 + 回弹）而不是固定时长的缓动；按下立即反馈、展开收起有高度过渡、位置变化用位移过渡；遵从系统的"减弱动态效果"。
- **外观**：跟随系统 / 浅色 / 深色三档，记住选择，系统外观变化时自动跟随；深色贴近 DeepSeek Harness，浅色按同样的层级关系推导。
- 完整页面原型：`prototypes/app-prototype.html`。设计规范（变量、组件、动效参数）另行整理成文档。
- 本 spec 引用的原型（`prototypes/` 下的侧栏、对话区、图标对比、完整页面）按"用完即弃"的约定保存在 `prototype/ui` 分支，不进 `main`。

### 侧栏

参考 Paseo 的工作区模型，侧栏按"项目 → 工作区"组织，会话放在工作区里，以对话区顶部的标签页呈现（见"对话区"）；另有不绑定工作区的"对话"。尺寸和样式按 DeepSeek Harness 对齐（宽 270、行高 34、14px）。原型讨论过程中先后比较过"会话平铺 + 彩色 git 图标 + worktree 折叠区"等方案（`prototypes/sidebar-prototype.html`），最终改为工作区模型：会话属于哪个 worktree 从靠颜色对应变成结构上的包含，合并状态直接挂在工作区上。

**概念关系**

```
项目（一个 git 仓库或目录）
 ├── 本地工作区（项目目录本身，每个项目一个）
 └── worktree 工作区（每个 worktree 一个，含不是 Atrium 创建的"外部" worktree）
      │  工作区与目录一一对应
      └── 会话（目录下的 pi 会话文件）
           ├── 打开着的 → 对话区顶部的标签页
           └── 全部 → "历史"菜单
对话（不绑定项目和工作区的会话，⌘N 新建）
 └── 每个对话一个空目录 ~/.atrium/chats/<id>/，宿主按目录认出它们
```

- 工作区和目录一一对应：pi 按工作目录保存会话，宿主按会话的工作目录把它归到对应的工作区，没有歧义。以后确实需要多个工作区共用一个目录（按任务分组）时再放开。
- MVP 1 的工作区：每个项目自动有一个本地工作区；`git worktree list` 识别出的每个 worktree 是一个工作区。新建 worktree 工作区、归档并清理 worktree 放到阶段 1 第 3 步。
- 对话用于和项目无关的提问。pi 必须有工作目录，所以每个对话给一个独立的空目录，agent 写的文件互不干扰；"移到某个项目"以后再做。
- Atrium 只保存索引：项目列表（目录、显示名）；工作区（所属项目、本地或 worktree、目录、分支、自定义名称、创建时的起点提交、是否外部、是否归档）；每个工作区和"对话"打开着哪些标签页、当前是哪一个；会话的归档状态、出错是否已看过。不保存对话内容。

**收件箱**

- 只放"等你处理"和"出错"的会话，跨所有项目和对话汇总，按状态优先级、再按时间排序。第一行是会话标题和最近活动时间，第二行是"项目 · 工作区"，对话写"对话"。
- 最多显示 5 条，其余收成"还有 N 条"，点击展开；展开后末尾是"收起"。
- 点击：切到会话所在的工作区（或"对话"），没打开的会话补开一个标签页并激活。收件箱行和工作区行同时高亮：一个表示正在看的会话，一个表示所在的工作区。工作区所在的项目是收起的，不自动展开，项目行带上选中底色。
- 离开收件箱：待审批、待回答、待授权要等问题解决（看一眼不算）；出错的会话打开过即算已看过，移出收件箱，但标签页和工作区行上的出错图标保留，直到下一次运行开始。
- 不单独设"运行中"分区。

**搜索**

- 点"项目"标题右侧的搜索按钮，搜索框在原位展开；搜索框和它上面的内容（新建对话、收件箱、"项目"标题）都不动，项目列表和"对话"换成搜索结果。
- 结果分两组：工作区（名称 + 所属项目 + 合并状态）、会话（与收件箱同样的两行格式，包含对话）。点击工作区切过去；点击会话打开它。
- 匹配工作区名和会话标题；全文搜索以后再做。清空或关闭搜索框，恢复项目列表。

**项目与工作区**

- 项目可折叠。项目行：文件夹图标、名称；悬停出现"+"（新建工作区）；收起时，右侧显示待合并的 worktree 数和其中会话的最高优先级状态。展开时不显示待合并数，下面每个工作区都能看到。
- 工作区在项目下缩进显示，不放图标，名称和项目名对齐。本地工作区排第一；其余 worktree 按创建时间倒序，位置稳定，不因为 agent 跑完一轮而跳动；已合并、已移除的变淡、排在最后。
- 工作区行：名称、合并状态、行尾是其中会话的最高优先级状态（空闲时不显示）。"本地""外部"不单独标注，只在悬停提示里说明。合并状态是纯文字标签、不加底框：未提交、待合并前面有橙色小圆点，`↑N` 用橙色加粗，`✓ 已合并` 用绿色，已移除用最淡的灰色。
- 点击工作区：切过去，恢复它上次激活的标签页；没有打开的会话时显示这个工作区的空状态。
- 悬停 worktree 工作区出现"查看改动 / 合并"（未合并时）或"清理"（已合并时），阶段 1 第 3 步实现；MVP 1 只读显示合并状态。
- "···"菜单：重命名；在访达中显示；归档工作区并清理 worktree（阶段 1 第 3 步）。

**对话**

- 侧栏底部的"对话"分区列出最近 5 个对话（标题、时间、非空闲时的状态），更多的点"全部 N 个对话"，在"历史"里看。
- 选中对话时，对话区顶部的标签页是打开着的对话，标签栏的"+"新建对话；新对话的空状态提示"不绑定项目和工作区"。
- 标签栏的"+"在当前所在的地方新建：在工作区里就是这个工作区的会话，在"对话"里就是新对话。

**命名**

- 项目名：默认取目录名，可以重命名。添加的目录与已有项目同名时，自动在后面加序号，如 `app (1)`，并提示可以重命名；手动重命名成已有的名字时，提示重名、不保存。
- 工作区名：默认是分支名，跟着分支变化。本地工作区取项目目录当前检出的分支（不一定是 `main`）；worktree 取它检出的分支；处于 detached HEAD 时用目录名，悬停显示短 commit 号；项目不是 git 仓库时，本地工作区用目录名。
- 工作区可以重命名：自定义名称只存在 Atrium 的索引里，不改 git 分支名；改过名的工作区悬停时显示分支名；名称清空即恢复为分支名。
- 会话标题，按以下顺序取第一个有值的：
  1. pi 的会话名：手动重命名和模型生成的标题都写在这里（`set_session_name`），终端 pi 也能看到。
  2. 兜底标题：第一条用户消息的第一行，去掉 Markdown 符号和首尾空白，过长由界面省略；只有图片时显示"图片"。兜底标题只用于显示，不写回 pi。
- 自动生成标题：会话（含对话）的第一轮运行结束（`agent_settled`）时，如果会话还没有名字，宿主用一次性调用让模型起一个短标题（与用户消息同语言，中文不超过 16 个字，不带标点和引号），写回 pi 的会话名，替换掉兜底标题；标签页、收件箱、"历史"同步更新。
  - 输入：第一条用户消息和第一条回复的开头，截断到约 2000 字符。
  - 调用：`pi --mode json -p --no-session`，默认用当前会话的模型，设置里可以指定一个更便宜的模型。
  - 已经有名字的会话不再生成，因此不会覆盖手动重命名；生成过程中用户手动改了名，丢弃生成结果。
  - 失败时保留兜底标题，在下一轮运行结束时再试一次。
  - 没在 Atrium 里跑过的历史会话（比如终端 pi 里开的）不批量补生成，仍显示兜底标题。
- 在终端 pi 里开的会话同样显示，不区分来源。

**worktree 合并状态**：和会话状态是两个维度。会话状态回答"agent 需不需要我"，合并状态回答"这批改动收尾了没有"。

| 状态 | 判断 | 显示 |
|---|---|---|
| 有未提交的改动 | worktree 内 `git status` 不干净 | `• 未提交` |
| 有未合并的提交 | 未判定为已合并，且分支比主干多 N 个提交 | `↑N`（悬停说明"未合并"） |
| 无改动 | 干净，且分支还停在起点（见下文） | 不显示标签，不变淡 |
| 已合并 | 干净，分支离开过起点，且已进入主干（见下文） | `✓ 已合并`，变淡，提供"清理"入口（阶段 1 第 3 步） |
| 已移除 | worktree 目录不存在（`git worktree list` 标为 prunable） | `已移除`，变淡 |

- 主干默认取 `origin/HEAD` 指向的分支，每个项目可以单独修改。比较对象用远程分支（如 `origin/main`），宿主在后台定期 `git fetch`（窗口获得焦点时、每隔几分钟），因为合并常在 GitHub 上完成，本地 `main` 可能还没更新。
- 判断已合并，按顺序：
  1. 分支已在主干历史中（`git merge-base --is-ancestor`）→ 已合并。覆盖普通 merge 和快进。
  2. 否则用 `git merge-tree --write-tree <主干> <分支>` 在内存中模拟合并，结果与主干的 tree 相同 → 已合并。覆盖 squash、rebase、cherry-pick；主干之后改了别处不影响判断；主干回滚了该改动则判为未合并。模拟合并有冲突，一律视为未合并。需要 git 2.38 以上。
- 区分"无改动"和"已合并"：刚建好的 worktree 分支天然在主干历史里，只看第 1 步会误判为已合并。Atrium 新建 worktree 时记下起点提交；分支最新提交仍等于起点 → 无改动，离开过起点后又进入主干 → 已合并。外部 worktree 没有记录起点，看分支的 reflog 里有没有过它自己的提交。
- 计算时机：不持续监听文件。对相关的 worktree 重算：其中的会话一次运行结束时、窗口获得焦点时、后台 `git fetch` 之后（只重算 `↑N` 和已合并，不跑 `git status`）。已合并的判断结果按"分支提交 + 主干提交"缓存；同时最多跑 4 个 git 命令。
- 成本：`git status` 最贵（大仓库可能几百毫秒），其余都是毫秒级。
- 不提示"搁置多久"。

**会话状态**：一个会话同时满足多个状态时，按下表从上到下取第一个；工作区行、项目行（收起时）显示其中会话的最高优先级状态。图标是纯线性图标、只给图标上色，不加底色；不同状态用不同的形状或动画区分，不只靠颜色；悬停显示具体原因。

| 大类 | 具体原因 | 图标 | 版本 |
|---|---|---|---|
| 等你处理（橙色） | 待审批：工具调用等批准 | 手掌 | MVP 2 |
| | 待回答：extension 对话框提问 | 问号圆圈 | MVP 1 |
| | 待授权：模型订阅登录过期、MCP server 需要登录等 | 钥匙 | MVP 1 尽量识别，识别不了就显示为出错并提示重新登录 |
| 出错（红色） | 进程异常退出、运行出错 | 感叹号圆圈 | MVP 1 |
| 运行中（强调色） | 正在执行 | 转动的圆弧 | MVP 1 |
| 已完成未读（强调色） | 不在查看时跑完了 | 小圆点 | 阶段 1 第 3 步 |
| 空闲 | — | 不显示 | MVP 1 |

**操作**

| MVP 1 | 以后 |
|---|---|
| 添加项目、从侧栏移除项目（不删除文件） | 新建 worktree 工作区（阶段 1 第 3 步） |
| 新建对话：侧栏按钮、⌘N，不绑定工作区；新建会话：标签栏的"+"，在当前工作区 | 归档工作区并清理 worktree（阶段 1 第 3 步） |
| 重命名、归档会话（标签栏右侧"···"）：归档只在 Atrium 里隐藏，不删除 pi 的会话文件；重命名工作区（工作区"···"）、项目 | 一个目录多个工作区、置顶、彻底删除、全文搜索 |
| 搜索工作区和会话（"项目"标题右侧的搜索按钮） | 分叉关系的展示、把对话移到项目里 |

### 对话区

调研了 Claude Code 桌面端、Codex 桌面端、Paseo、Cursor、Zed，共同方向是：**突出结果，折叠过程；运行中的输入可以排队或插话**。MVP 1 只做纯对话能力，审查面板、文件路径操作放到以后。

经原型讨论（`prototypes/conversation-prototype.html` 方案 A）确定采用"过程折叠条"：跑完后过程收成一行摘要，点击展开；没有采用时间线、轮次卡片两种结构。

```
┌──────────────────────────────────────────────────────────┐
│ [◌ 设计侧栏交互 ×] [✋ 重构宿主…] [调研 pi RPC] + ◷历史⌄  👁 摘要模式⌄ ··· │ ← 标签栏：本工作区打开着的会话
├──────────────────────────────────────────────────────────┤
│                                          ┌──────────────┐ │
│                                          │ 🖼 侧栏草图.png │ │ ← 附件：文件卡片
│                              帮我把侧栏改成收件箱的结构      │ ← 用户消息（圆角 22）
│                                                22:31  ⧉  │ ← 时间、复制（常驻）
│ 已完成，用时 2 分 13 秒 · 读了 8 个文件 · 1 条命令失败  ⌄    │ ← 过程标题行，下有细分隔线
│ 改好了，主要改动是……（Markdown）                             │ ← 最终回复
│ ⧉  ≣  🗄 用量 18K tok   22:31                              │ ← 复制、复制整轮、本轮用量、时间（常驻）
│ ────── ⇲ 上下文已自动压缩 · 压缩前 152K tokens ──────         │ ← 系统事件
├──────────────────────────────────────────────────────────┤
│ 排队 1 · 本次运行结束后依次发送                               │
│   再补一个边界测试                       [插话] [编辑] ✕     │
│ ╭──────────────────────────────────────────────────────╮ │
│ │ 发消息或描述任务                                        │ │
│ │ ⊕  ⚡ 直接执行                     gpt-6-sol medium ⌄  ⬆ │ │
│ ╰──────────────────────────────────────────────────────╯ │
│       ⏲ 1 轮 7 步 · 48 tok/s   🗄 1.3M tok · 缓存命中 73%   ◔ 42%   │ ← 状态栏：居中，悬停弹出详情
└──────────────────────────────────────────────────────────┘
```

**标签栏**（对话区顶部）

- 显示当前工作区"打开着的"会话，每个标签是一个会话：标题、非空闲时的状态图标、关闭按钮。关闭标签只是收起，会话保留在"历史"里。
- "+"在当前工作区新建会话；"历史 ⌄"列出这个工作区的全部会话（状态、时间、是否已打开），点击即在标签页中打开。
- 右侧是显示模式和"···"（重命名、归档当前会话）。
- 工作区没有打开的会话时，对话区显示空状态："工作区名 · 项目"，直接在输入框里输入就会新建会话。
- MVP 1 同一时间只跑一个会话：离开正在运行的会话（切换标签、切换工作区、关闭其标签）时，提示会中断它。
- 以后的"对话 / 轨迹"是单个会话内部的视图切换，和会话标签页不冲突，放在对话区里另找位置（MVP 2）。

**显示模式**（参考 Claude Code）：摘要（默认）/ 思考 / 详细，用 Ctrl+O 切换，全局记住选择。入口是标签栏右侧的"👁 摘要模式 ⌄"。

| 内容 | 运行时 | 跑完后（摘要模式） |
|---|---|---|
| 推理过程 | 实时显示 | 折叠成"思考了 N 秒"；思考模式下展开 |
| 只读操作（读文件、搜索、列目录） | 连续的几个合并成一行，如"探索：读了 5 个文件，搜索了 2 次" | 收进过程摘要 |
| 命令（bash） | 一行"运行 · 命令"，右侧显示运行中 / 通过 / 退出码；详情块里实时滚动输出 | 收进过程摘要；有失败的命令时，标题行末尾加红色标记"N 条命令失败"，不单独展开（agent 常常会自己修好，展开显示太吵） |
| 文件改动（edit / write） | 一行"编辑 · 文件路径 +N −M"，详情块里显示 diff（`edit` 用 `details.diff`），带行号和增删竖条 | 收进过程摘要，展开可看 diff |
| 系统事件（上下文压缩、自动重试） | 一行灰色提示，压缩时带压缩前的 token 数 | 保留 |
| 对话框（待回答、待授权） | 消息流底部的卡片，直接在卡片上作答 | 显示你的回答 |

详细模式下所有步骤都展开。

**过程的呈现**（参考 DeepSeek Harness）：

- 标题行：运行时显示带扫光效果的"进行中"；跑完后显示"已完成，用时 N · 读了 … · 跑了 …"，被中断时显示"已停止，用时 N"。展开时标题行下方有一条细分隔线。
- 步骤是单行列表："图标 + 动词 · 对象"，文件路径带虚线下划线，编辑步骤在末尾显示 +N −M。点击某一步，在下方的深色详情块里显示内容（左上标"输出 / 改动"，右上标工具名）。不做成卡片。

**运行中输入：默认排队，可插话**

- 按回车：agent 空闲时直接发送；运行中进入排队。⌘+回车：直接插话。
- 排队中的消息显示在输入框上方，可以编辑、删除、点"插话"。
- 插话调用 pi 的 `steer`：在 agent 当前这批工具调用执行完、下一次请求模型之前送达，不是立刻打断。界面上标注"下一步前送达"；要立刻停下用"停止"。
- 排队由宿主管理，不使用 pi 的 `follow_up` 队列：本次运行结束（`agent_settled`）后，宿主依次把下一条作为 `prompt` 发出。这样编辑、删除、调整顺序都由 Atrium 控制。
- 停止后，排队暂停、不自动发出，由你决定继续发送还是清掉。

**消息下方的信息**（常驻显示，参考 DeepSeek Harness）：

- 用户消息下方：时间、复制。
- 回复下方：复制回复、复制整轮、本轮用量（这一轮的输入 + 输出 token）、时间。不做点赞、点踩、分享。

**输入框**：提示文字为"发消息或描述任务"；左下角是添加图片和"⚡ 直接执行"标签（MVP 1 没有审批，标签只用来说明工具调用会直接执行；MVP 2 变成审批模式的选择器）；右下角是模型与推理强度、发送 / 停止。附件显示成文件卡片。

**状态栏**（参考 DeepSeek Harness）

位于输入框正下方，居中。按语义分组，每组是"图标 + 一行摘要"；悬停时这组出现浅色底，并在上方弹出详情卡片（标题行 + 细分隔线 + 键值列表），鼠标可以移进卡片。

| 分组 | 默认 | 摘要 | 详情卡片 | 数据来源 |
|---|---|---|---|---|
| 会话统计 | 显示 | "N 轮 N 步 · 48 tok/s" | 模型用时、首 token 平均（TTFT）、输出速度（TPS） | 宿主计时：模型用时累计每次请求从发出到 `message_end`；TTFT 是发出请求到第一个增量；TPS 是最近一次回复的输出 token ÷ 流式输出时长 |
| Token 用量 | 显示 | "1.3M tok · 缓存命中 73%" | 总量；缓存命中、未缓存输入、缓存读取、缓存写入、输出（其中推理） | `get_session_stats` 的 `tokens`；每条助手消息的 `usage`。缓存命中 = `cacheRead` ÷（`input` + `cacheRead` + `cacheWrite`） |
| 上下文 | 显示 | 圆环 + "42%" | "上下文已用 42% · ~84K / 200K"；分段彩色条与图例：系统提示词、工具定义、对话消息 | 见下文"上下文分段"。超过 70% 变黄、超过 85% 变红；压缩后到下一次回复前显示"—" |
| 费用 | 不显示 | "≈ $0.45" | 按 API 价格折算，订阅用户不实际付费 | `get_session_stats` 的 `cost` |

- MVP 1 就支持配置显示哪些分组：右键状态栏，或点详情卡片底部的"自定义状态栏"，配置全局保存。
- 分组做成注册表：每组包含 id、名称、摘要、详情卡片、是否默认显示。以后加指标：给某组的卡片加一行，或注册新的一组，不改状态栏本身。
- 订阅额度不在对话面板里显示。

### 关键流程

- **工作区与会话列表**：宿主用 `git worktree list` 列出项目的工作区（本地工作区 + 各 worktree）。pi 的 RPC 没有列出历史会话的命令，宿主直接读 `~/.pi/agent/sessions/--<路径>--/*.jsonl`（Paseo 也是这样做的），按会话所在目录归到对应的工作区，从中取会话 id、时间、会话名和第一条用户消息（按"侧栏 · 命名"得出标题）。Atrium 自己只保存索引（见"侧栏 · 概念关系"）。
- **恢复会话**：以 `--session <文件>` 启动 pi，再用 `get_messages` 取回当前分支的消息，渲染出历史对话。
- **流式输出**：`message_update` 里的 `text_delta` 和 `thinking_delta` 追加到对应的内容块；`message_end` 到达时，用完整消息替换拼接结果。
- **运行结束**：以 `agent_settled` 为准，而不是 `agent_end`，因为 pi 在 `agent_end` 之后还可能自动重试或压缩。
- **运行中继续输入**：宿主维护排队，`agent_settled` 后依次发出；插话调用 `steer`（见上文"对话区"）。
- **中断**：先 `clear_queue`，再 `abort`。否则已经插话、还没送达的消息会让运行继续下去（Paseo 踩过这个坑）。宿主自己的排队暂停，不自动发出。
- **图片**：粘贴或拖入的图片转成 base64，放进 `prompt` 的 `images` 字段。只有当前模型的 `input` 包含 `image` 时才允许添加图片，否则提示当前模型不支持。
- **工具卡片**：
  - `bash`：显示命令和输出，输出随 `tool_execution_update` 实时刷新
  - `read`：显示文件路径和行范围
  - `edit`：用结果里的 `details.diff` 显示 diff
  - `write`：显示文件路径和写入的内容
  - 其他工具（包括 MCP 工具）：显示工具名、参数和结果文本
- **上下文分段**：总量用 `get_session_stats` 的 `contextUsage.tokens`（pi 的实际值）。系统提示词和工具定义从会话记录还原：pi 在第一次请求时把提示词的各个分段（`sections`）和工具声明（`toolsAdded`）写成一条系统消息，之后的变化也写成系统消息（按名字修改分段、`toolsAdded` / `toolsRemoved`）；压缩条目里存有完整的检查点（`systemMessage`）。宿主用 `get_entries`（可用 `since` 增量获取）拿到条目，沿当前分支回放，得到当前的提示词和工具集，再按字符数估算 token；对话消息 = 总量 − 系统提示词 − 工具定义。分段数字标"~"，总量不标。新会话在第一次请求前没有系统消息，只显示总量。（依据 pi 文档 `session-format.md` 与 `rpc-mode.ts` 中 `get_entries` 的实现，实施时用真实会话验证。）
- **对话框**：pi 发出 `extension_ui_request` 时，对话框类（`select` / `confirm` / `input` / `editor`）显示为卡片，回答后发 `extension_ui_response`；带超时的显示倒计时。单向通知类（`notify` 等）暂时只记录、不显示。
- **断线重连**：UI 重连后，宿主发一份当前会话的快照（消息列表和运行状态），再接着推送后续事件。

## 备选方案

| 方案 | 为什么不用 |
|---|---|
| SDK 嵌入 pi | 见 ADR-0002，放弃进程隔离 |
| Atrium 自己保存对话记录 | 和 pi 的会话文件重复，两份数据会不一致；对话历史归 pi（见 [架构总览](../architecture/overview.md)） |
| 一开始就支持多个会话同时运行 | 进程管理和界面状态都会翻倍；放到阶段 1 第 3 步 |

## 风险与待定问题

- [ ] **没有审批的风险**：agent 可能误删文件或执行危险命令。缓解：MVP 1 只在 git 仓库里使用，出问题用 git 回滚。
- [ ] **pi 适配器用 pi 自带的 `RpcClient`，还是自己实现 JSONL 客户端**：前者省事，官方也推荐；后者和 pi 的依赖更松（Paseo 选了后者）。倾向先用 `RpcClient`，封装在适配器内部，以后可以替换。
- [ ] **包管理器**：倾向 pnpm workspaces。
- [ ] **UI 组件库和状态管理**：组件用 shadcn；`client` 里的状态管理库待定，要求不依赖 DOM。
- [ ] **pi 版本兼容**：会话文件格式和 RPC 都可能变化。宿主启动时检查 pi 版本，低于最低版本就提示升级。

## 实施计划

每一步都先跑通再往下走：

1. monorepo 骨架；Electron 打开窗口，加载宿主提供的空白 UI

4. 工具卡片和 diff、显示模式
5. 项目、工作区、会话标签页和恢复会话
6. 中断、排队与插话、模型和推理强度切换、图片、对话框卡片、状态栏
7. 自用一周，记录问题
