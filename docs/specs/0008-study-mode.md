## 背景与目标

学东西也是日常（路线图"用真实的日常任务驱动"）。现在想用 Atrium 学一门新东西，只能开一个普通对话，进度、漏洞、笔记全靠自己记，换一个会话就断了。

方法论取自 sairahul1 的那篇文章（6 段提示词），对应到这里：

| 文章里的一步 | 这里 |
|---|---|
| 排一个从新手到熟练的阶梯 | 讨论时排出这个人的**阶梯** |
| 20 小时的计划 | 每一级排成一串**步骤**（课 + 过关的几步） |
| 测到答不上来为止，找出漏洞 | 每节课后的**测验**，漏洞记下来 |
| 一页速查表 | 每一级的"速查表"那一步 |
| 挑 5 份资料 | 讨论时联网挑资料 |
| 费曼法：讲给 12 岁的孩子听 | 针对一个漏洞开**费曼**会话 |

目标：侧栏有一个"学习"入口，管理所有学习方向。每个方向按这套方法一级一级学下去；每件事一个会话，进度靠方向目录里的档案衔接，随时能接着学。

## 非目标

- 间隔复习、到期提醒。
- 手机端（第一版只做电脑）。
- 和项目打通（在项目里学、把学到的带回项目），第二步再说。
- 图片生成（SPEC-0007 的非目标）。
- 单独的方向配置页、设置里改学习目录。
- 多人共用一个方向。
- 讨论结束后再改阶梯（2026-11-05 用户定第一版不做）。

## 需求

1. 当我想学一样东西，我希望直接说想学什么，由对话来定名字、目标和起点，不用填表。
2. 我希望每个方向都有一份按我排的阶梯：几级、每级叫什么、学什么、怎样算过关，都在讨论里定。
3. 我希望随时知道自己在第几级第几步、下一步做什么，一键开始。
4. 当我学完一节课，我希望马上被测一测，漏洞记下来，再针对漏洞补上。
5. 当我隔了几天回来，我希望 agent 记得我学到哪、哪里不会，不用我重新交代。
6. 当一级学完，我希望有速查表、过关项目和综合测验，过了再升级。
7. 当某个概念有动态过程，我希望 agent 用可交互的演示讲（SPEC-0007）。
8. 我希望所有学习的东西都在一个我看得见的目录里，换个工具也能读。

## 方案设计

### 入口（原型丁）

- 侧栏最上面一行"学习"（学士帽图标），点开主区是**学习首页**。侧栏不列方向。
- 这一行汇总所有方向的状态：有会话在跑显示转圈，有会话在等你回答显示"待回答"（同现有的关注状态，也进收件箱）。
- 学习首页：
  - 没有方向时：一句话和"新建方向"。
  - 有方向时：最上面"继续"，是**上次打开的方向**（2026-11-05 用户定）和它的下一步，一键开始；下面是所有方向的卡片：名字、共几级、当前级和步数、漏洞数、点阵进度。讨论中的方向标"讨论中"。点卡片进入方向主页，在主页的会话列表里点开讨论会话接着谈（2026-11-06 用户定：不要"继续讨论"按钮）。
  - 卡片的"···"：置顶、改名、归档。

### 方向是一种新容器

- 和工作区、对话并列的第三种 `SessionContainer`：**Direction**（学习方向）。
- 目录固定在 `~/Atrium/Learning/<目录名>/`，不能在设置里改（2026-11-05 用户定）。放在用户看得见的地方，不放 `~/.atrium/`：档案是给人看、可以拿别的工具读的。
- 目录里有 `.atrium-study.json` 才算一个方向（标记文件，2026-11-05 用户定）；宿主扫描 `~/Atrium/Learning/` 的子目录得到方向列表。id 是 `lrn_<目录名>`。用户删掉目录，方向就没了。
- 方向里所有会话的工作目录都是方向目录。会话的归属、归档、置顶做法同对话（domain-model §1 Chat）。
- **归档方向 = 把目录移到单独的归档目录** `~/Atrium/Learning/Archive/<目录名>/`（2026-11-05 用户定）。扫描只看 `~/Atrium/Learning/` 下一层、带标记文件的目录，所以 `Archive/` 本身不算方向，新建方向也不用这个目录名。归档的方向在学习首页的"已归档"里，会话只能看、不能继续（只读地看，宿主直接读会话文件，不起 pi；工作目录不在原处了）；恢复就移回原处，原处已有同名目录时拒绝，错误码 `study.restore_conflict`。
- 学习会话就是普通的 pi 会话，只是索引里多一条"用途 + 第几级第几步"（见"接口与数据"）。

### 新建方向：直接进对话（同新建工作区）

- 点"新建方向"，主区是一个只有输入框的页："想学点什么？"（原型第 2 屏）。没有对话框、没有表单。这时什么都没建，关掉不留东西。
- 发出第一条消息后，宿主：
  1. 让 AI 按这条消息起显示名和英文目录名（同 worktree 的中文名那套；起不成时显示名取消息的第一行、目录名用随机名，不做拼音（2026-11-06 用户确认）；重名时加后缀）。
  2. 建目录，写 `.atrium-study.json`、方法论的 `AGENTS.md`，建 `lab/` 并 `git init`。
  3. 在目录里开"讨论"会话，把这条消息交给它。
- pi 必须在目录存在之后才能启动（工作目录），所以顺序不能反。

### 讨论：定档、摸底、排阶梯

讨论会话里 agent 做三件事：

1. **定档**：目标、基础、每周时间、语言或环境。只问第一条消息里没说到的，用提问卡片（`ask_user`）。
2. **摸底**：一次一题、由浅到深、立刻判，不打分，只为定起点和能跳过哪几级。
3. **排阶梯**：联网挑 5 份资料；按这个人的目标排几级，每级有名字、内容、过关标志（2026-11-05 用户定：**阶梯每次按人排，级数 2～6 级**，跳过的级也算在内）；问你要不要改；定下后排出起点那一级的步骤。

- agent 可以在讨论中途改显示名（比如"后端"改成"Node 后端"），目录名不改。
- **写出阶梯才算讨论结束**。没有阶梯的方向一直是"讨论中"，主页只列出它的会话，点讨论会话接着谈（2026-11-05 用户定：阶梯是必须的；2026-11-06 去掉"继续讨论"）。

### 一级 = 一串步骤（步骤条）

- 每一级是一串同样结构的步骤：先是这一级的几节课，然后是**速查表、过关项目、综合测验、升级**。不单独做过关清单（2026-11-05 用户定）。
- 每一步的状态：没开始 / 进行中 / 完成。
- 课这一步里有三小步：**上课 → 测验 → 补漏**。补漏不强制：测验后有漏洞时，下一步按钮是"跑费曼"，旁边可以"进入下一步"。
- "下一步"由宿主按进度算出来，不由 agent 说（见"下一步怎么算"）。
- **手动标完成**（2026-11-05 用户定要）：agent 忘了报告时，你可以在方向主页把一步（课这一步可以单标某一小步）标成完成，也能撤回。手动标的记 `"by": "manual"`，测验分数留空；之后 agent 再报告同一步，以 agent 的为准。

### 常驻步骤条（原型 C，2026-11-05 用户选）

- 方向主页和这个方向的每个学习会话，标签栏下面都有一条步骤条：当前级的名字、每一步一个小方点（课是方点，后面几步是圆点；做完的、当前的、没做的颜色不同）、当前这一步和小步的说明、下一步按钮（加一个次要按钮）。
- 它代替了早先设计里输入框上方的"学习胶囊"。
- 讨论中（还没有阶梯）：步骤条只写"讨论中，排出阶梯以后这里显示当前一级的步骤"。

### 方向主页

方向主页是标签栏最左边固定的一个标签（学士帽 + 方向名），关不掉，会话标签开在它右边，标签前的图标表示用途。主页内容（原型 C）：

- 标题、当前级、一句话定档（目标 · 语言 · 每周时间）。
- 当前步骤卡：第几步、做什么、上课/测验/补漏三小步、开始按钮。
- 这一级的全部步骤：做过的步骤下面挂着它的会话（上课、测验 + 分数、费曼），点开就是那个会话。
- 右栏：阶梯（各级的名字，跳过的、当前的、没到的）、漏洞（来自哪一题，已补的划掉）、其他会话（讨论、随口问）、档案（目录里的文件，点开用现有的文件预览）。

### 会话的用途

| 用途 | 怎么开 | 做什么 | 写回 |
|---|---|---|---|
| 讨论 | 新建方向时；在方向主页的会话列表里点开 | 定档、摸底、排阶梯 | 名字、阶梯、起点那一级的步骤、资料、定档 |
| 排计划 | 升级时 | 按阶梯和剩下的漏洞排下一级的步骤 | 这一级的步骤 |
| 上课 | 课这一步的"开始上课" | 讲一点、在 `lab/` 里动手一点、看你的代码；必要时放演示 | 笔记；这一步"上课完成" |
| 测验 | 上课完成后的"开始测验" | **上课会话的子对话，带上下文**（SPEC-0002 用户开的子对话）；一次一题，选择题用提问卡片，答完立刻判、补讲 | 分数、漏洞 |
| 费曼 | 有漏洞时的"跑费曼"；漏洞旁的按钮 | 针对一个漏洞：先讲简单版，你讲回去，讲不清就补 | 漏洞标为已补；一份讲解笔记 |
| 速查表 | 速查表这一步 | 把这一级压成一页 | `cheatsheet.md` 里加这一级 |
| 过关项目 | 过关项目这一步 | 在 `lab/` 里做，按过关标志验收 | 这一步完成 |
| 综合测验 | 综合测验这一步 | 整级内容，10 题由浅到深 | 分数、漏洞 |
| 随口问 | 主页标签栏的"+" | 普通会话，带方向的上下文 | 不改进度 |

- 开一个有用途的会话时，宿主发隐藏命令 `/atrium-study <用途> <base64url JSON>`（同 ADR-0013 的做法，`/atrium-` 只有宿主能发），扩展把它展开成给模型的提示。消息气泡由界面显示成"上课 · 第 2 级第 4 步"之类，宿主不产出给用户看的文字。
- 一件事一个会话（2026-11-05 定），会话之间靠档案衔接：每个会话开始时 agent 读方向的进度、上一节的笔记、没补的漏洞。
- 各用途展开后的提示词**先照推文的 6 段提示词写**（讨论用"排阶梯"和"挑资料"，上课用"20 小时"，测验用"考到出错"，速查表用"速查表"，费曼用"费曼"），用起来再慢慢调（2026-11-05 用户定）。

### 下一步怎么算

宿主按进度决定步骤条上的按钮，agent 只负责报告"做完了什么"：

| 当前这一步 | 情况 | 主按钮 | 次要按钮 |
|---|---|---|---|
| 课 | 还没上 | 开始上课 | — |
| 课 | 上课完成、没测 | 开始测验 | 以后再测 |
| 课 | 测完、这一步有没补的漏洞 | 跑费曼 | 进入下一步 |
| 课 | 测完、没有漏洞，或漏洞都补了 | 进入下一步 | — |
| 速查表 / 过关项目 / 综合测验 | 没做 | 生成速查表 / 开始项目 / 开始测验 | — |
| 升级 | 前面的都完成 | 升级 | — |

正在跑的会话里，按钮是"回到这个会话"，不重复开。

### 升级

- 升级是步骤条的最后一步，点了弹确认（原型第 13 屏）：升到第几级"名字"；"把这一级的 N 个会话一起归档"默认勾上，可以取消（档案和笔记都留着，会话能在"已归档"里恢复）；没补的漏洞带到下一级。
- 确定后开一个"排计划"会话，排下一级的步骤。下一级到这时才排，用得上前面学下来的情况。
- 最后一级过关后，方向标"已学完"，还能随口问、复习。

### 方向目录

```
~/Atrium/Learning/<目录名>/
├── .atrium-study.json   标记 + 进度（见"接口与数据"），只经扩展工具改
├── AGENTS.md            方法论规则 + 定档；pi 每个会话都读
├── resources.md         挑的资料和使用顺序
├── cheatsheet.md        每一级一节
├── notes/               每节课一篇，费曼的讲解
├── visuals/             演示（SPEC-0007）
└── lab/                 练习代码，自己的 git 仓库
```

- **pi 读 AGENTS.md 不需要信任目录**（pi 1.5.0 源码核实，`resource-loader.js` 的 `loadProjectContextFiles`：从工作目录一路往上找 `AGENTS.md`、`CLAUDE.md`，和信任无关；`.pi/prompts`、`.pi/skills`、`.pi/SYSTEM.md` 才要信任）。所以方法论放 AGENTS.md，命令由 Atrium 扩展注册，不放 `.pi/prompts`，方向目录不用信任。注意上层目录（`~/Atrium/`、`~`）的 AGENTS.md 也会被读到。
- AGENTS.md 由宿主建方向时写入方法论规则（英文，给模型看；你可以改），讨论时 agent 在后面补定档。规则包括：一次只讲一点、让学生动手、测验一次一题、不替学生写 `lab/` 里的代码、按内容挑展示形式（原型"展示形式"第 6 屏）、每个会话开始先读进度和漏洞。

### 演示

用 SPEC-0007，目录是 `visuals/`，文件名 `<级>-<步>-<名字>.html`。学习模式在 AGENTS.md 里多两条：每节课最多一个演示；最多加一个让学生先猜的问题，猜的结果作为一条"来自演示"的消息回到会话里。方向主页的档案里列出演示，笔记里可以链过去。

### 联网

讨论时挑资料、上课时查新版本的用法，用 pi 里默认装好的联网工具，也就是 Atrium 扩展自带的 `web_search`、`web_fetch`（ADR-0014，2026-11-05 用户定）；不另装别的搜索。没有配置搜索的 key 时，agent 只凭自己的知识挑资料，并在 `resources.md` 里注明没有联网核对。

## 接口与数据

### `.atrium-study.json`

```jsonc
{
  "version": 1,
  "name": "Node 后端",                 // 显示名，讨论中可以改
  "createdAt": "2026-11-05T10:12:00Z",
  "profile": {                         // 定档，给界面显示一句话用；详细的在 AGENTS.md
    "goal": "能独立写并部署一个 Node 服务",
    "weeklyHours": "4-8", "language": "TypeScript"
  },
  "ladder": [                          // 没有就是"讨论中"
    { "id": "l1", "name": "能跑的 API", "topics": "HTTP、REST、增删改查", "pass": "一个增删改查服务", "state": "skipped" },
    { "id": "l2", "name": "数据和登录", "topics": "…", "pass": "带登录的 API，有测试", "state": "current" }
  ],
  "steps": {                           // 只有排过的级才有
    "l2": [
      { "id": "s1", "kind": "lesson", "title": "关系建模", "lesson": "done", "quiz": { "score": 42, "of": 50 } },
      { "id": "s2", "kind": "lesson", "title": "事务", "lesson": "done", "quiz": { "by": "manual" } },  // 手动标的，没有分数
      { "id": "s10", "kind": "sheet", "title": "速查表", "state": "todo" }
    ]
  },
  "gaps": [
    { "id": "g1", "text": "分不清可重复读和串行化各挡住了什么", "from": { "level": "l2", "step": "s3", "question": 4 }, "fixedAt": null }
  ],
  "finishedAt": null
}
```

- 文件由宿主建、由扩展工具改（下面），agent 不用编辑工具直接改它。宿主读的时候校验，读不出的按"讨论中"显示，并提示文件坏了，不覆盖。
- 读文件时保留不认识的字段（同 domain-model"格式版本"）。

### 扩展工具（只有学习会话有）

| 工具 | 谁用 | 作用 |
|---|---|---|
| `study_set_name` | 讨论 | 改显示名 |
| `study_set_profile` | 讨论 | 写定档 |
| `study_set_ladder` | 讨论 | 写阶梯和起点（哪些级跳过）；写了讨论就算结束 |
| `study_set_steps` | 讨论、排计划 | 写某一级的步骤 |
| `study_report` | 上课、测验、费曼、速查表、过关项目、综合测验 | 报告这个会话做完了什么：上课完成、测验分数、过关项目验收通过…… |
| `study_add_gap` / `study_fix_gap` | 测验、费曼 | 记一个漏洞、标为已补 |

- 工具改的是宿主那边的状态：扩展把调用交给宿主（ADR-0013 的通道），宿主校验后写文件、推给界面。这样界面、步骤条、首页始终和文件一致。
- 每个工具只在对应用途的会话里有（同 SPEC-0002"哪些会话有哪些工具"的做法）。
- 工具说明写清楚什么时候调；agent 不调，进度就不动，你可以在主页上手动标完成（协议 `study.mark`，见"一级 = 一串步骤"）。
- `study_set_ladder` 的级数不在 2～6 之间时拒绝，错误码 `study.ladder_size`，参数带 `min`、`max`、`got`。

### 索引

## 备选方案

- **进度写在 Markdown 里（`ladder.md`、`plan.md`、`gaps.md`）**：设计稿里是这样画的。人和 agent 都好读，但宿主要从 Markdown 解析出步骤和状态，agent 写错一个格式主页就乱了。2026-11-05 用户定：进度只在 `.atrium-study.json`、只经工具改；Markdown 只放内容（笔记、速查表、资料）。
- **学习胶囊（输入框上方）**：原型 A、B 用它；用户选了 C，由步骤条代替。
- **方向主页的步骤竖排在阶梯里（A）、横条放在主页顶上（B）**：用户选了 C。
- **方向放在 `~/.atrium/` 下**：用户看不到、不方便用别的工具读。
- **一个方向一个长会话**：上下文会越来越长、压缩后丢细节；改为一件事一个会话、靠档案衔接。
- **测验另开一个新会话**：题目对不上这节课讲过的例子；改为上课会话的子对话。
