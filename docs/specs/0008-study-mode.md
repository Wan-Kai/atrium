## 背景与目标

学东西也是日常（路线图"用真实的日常任务驱动"）。现在想用 Atrium 学一门新东西，只能开一个普通对话，进度、漏洞、笔记全靠自己记，换一个会话就断了。

方法论取自 sairahul1 的那篇文章（6 段提示词），对应到这里：

| 文章里的一步 | 这里 |
|---|---|
| 排一个从新手到熟练的阶梯 | 讨论时排出这个人的**阶梯** |
| 20 小时的计划 | 每一级排成一串**步骤**（课 + 过关的几步） |
| 测到答不上来为止，找出漏洞 | 每节课后的**测验**，漏洞记下来 |
| 一页速查表 | 每一级的"速查表"那一步 |
| 挑 5 份资料 | 讨论时联网挑资料 |
| 费曼法：讲给 12 岁的孩子听 | 针对一个漏洞开**费曼**会话 |

目标：侧栏有一个"学习"入口，管理所有学习方向。每个方向按这套方法一级一级学下去；每件事一个会话，进度靠方向目录里的档案衔接，随时能接着学。

## 非目标

- 间隔复习、到期提醒。
- 手机端（第一版只做电脑）。
- 和项目打通（在项目里学、把学到的带回项目），第二步再说。
- 图片生成（SPEC-0007 的非目标）。
- 单独的方向配置页、设置里改学习目录。
- 多人共用一个方向。
- 讨论结束后再改阶梯（2026-11-05 用户定第一版不做）。

## 需求

1. 当我想学一样东西，我希望直接说想学什么，由对话来定名字、目标和起点，不用填表。
2. 我希望每个方向都有一份按我排的阶梯：几级、每级叫什么、学什么、怎样算过关，都在讨论里定。
3. 我希望随时知道自己在第几级第几步、下一步做什么，一键开始。
4. 当我学完一节课，我希望马上被测一测，漏洞记下来，再针对漏洞补上。
5. 当我隔了几天回来，我希望 agent 记得我学到哪、哪里不会，不用我重新交代。
6. 当一级学完，我希望有速查表、过关项目和综合测验；综合测验找出的漏洞建议补完再升级，但不硬拦，过没过由我自己判断（2026-11-09 ML3 改，原先写"过了再升级"）。
7. 当某个概念有动态过程，我希望 agent 用可交互的演示讲（SPEC-0007）。
8. 我希望所有学习的东西都在一个我看得见的目录里，换个工具也能读。

## 方案设计

### 入口（原型丁）

- 侧栏最上面一行"学习"（学士帽图标），点开主区是**学习首页**。侧栏不列方向。
- 这一行汇总所有方向的状态：有会话在跑显示转圈，有会话在等你回答显示"待回答"（同现有的关注状态，也进收件箱）。
- 学习首页：
  - 没有方向时：一句话和"新建方向"。
  - 有方向时：最上面"继续"，是**上次打开的方向**（2026-11-05 用户定）和它的下一步，一键开始；下面是所有方向的卡片：名字、共几级、当前级和步数、漏洞数、点阵进度。讨论中的方向标"讨论中"。点卡片进入方向主页，在主页的会话列表里点开讨论会话接着谈（2026-11-06 用户定：不要"继续讨论"按钮）。
  - 卡片的"···"：置顶、改名、归档。

### 方向是一种新容器

- 和工作区、对话并列的第三种 `SessionContainer`：**Direction**（学习方向）。
- 目录固定在 `~/Atrium/Learning/<目录名>/`，不能在设置里改（2026-11-05 用户定）。放在用户看得见的地方，不放 `~/.atrium/`：档案是给人看、可以拿别的工具读的。
- 目录里有 `.atrium-study.json` 才算一个方向（标记文件，2026-11-05 用户定）；宿主扫描 `~/Atrium/Learning/` 的子目录得到方向列表。id 是 `lrn_<目录名>`。用户删掉目录，方向就没了。
- 方向里所有会话的工作目录都是方向目录。会话的归属、归档、置顶做法同对话（domain-model §1 Chat）。
- **归档方向 = 把目录移到单独的归档目录** `~/Atrium/Learning/Archive/<目录名>/`（2026-11-05 用户定）。扫描只看 `~/Atrium/Learning/` 下一层、带标记文件的目录，所以 `Archive/` 本身不算方向，新建方向也不用这个目录名。归档的方向在学习首页的"已归档"里，会话只能看、不能继续（只读地看，宿主直接读会话文件，不起 pi；工作目录不在原处了）；恢复就移回原处，原处已有同名目录时拒绝，错误码 `study.restore_conflict`。
- 学习会话就是普通的 pi 会话，只是索引里多一条"用途 + 第几级第几步"（见"接口与数据"）。

### 新建方向：直接进对话（同新建工作区）

- 点"新建方向"，主区是一个只有输入框的页："想学点什么？"（原型第 2 屏）。没有对话框、没有表单。这时什么都没建，关掉不留东西。
- 发出第一条消息后，宿主：
  1. 让 AI 按这条消息起显示名和英文目录名（同 worktree 的中文名那套，用哪个模型见"ML2 定的细节"的"真实模型检查后改"；起不成时显示名取消息的第一行、目录名用随机名，不做拼音（2026-11-06 用户确认）；重名时加后缀）。
  2. 建目录，写 `.atrium-study.json`、方法论的 `AGENTS.md`，建 `lab/` 并 `git init`。
  3. 在目录里开"讨论"会话，把这条消息交给它。
- pi 必须在目录存在之后才能启动（工作目录），所以顺序不能反。

### 讨论：定档、摸底、排阶梯

讨论会话里 agent 做三件事：

1. **定档**：目标、基础、每周时间、语言或环境。只问第一条消息里没说到的，用提问卡片（`ask_user`）。
2. **摸底**：一次一题、由浅到深、立刻判，不打分，只为定起点和能跳过哪几级。
3. **排阶梯**：联网挑 5 份资料；按这个人的目标排几级，每级有名字、内容、过关标志（2026-11-05 用户定：**阶梯每次按人排，级数 2～6 级**，跳过的级也算在内）；问你要不要改；定下后排出起点那一级的步骤。

- agent 可以在讨论中途改显示名（比如"后端"改成"Node 后端"），目录名不改。
- **写出阶梯才算讨论结束**。没有阶梯的方向一直是"讨论中"，主页只列出它的会话，点讨论会话接着谈（2026-11-05 用户定：阶梯是必须的；2026-11-06 去掉"继续讨论"）。

### 一级 = 一串步骤（步骤条）

- 每一级是一串同样结构的步骤：先是这一级的几节课，然后是**速查表、过关项目、综合测验、升级**。不单独做过关清单（2026-11-05 用户定）。
- 每一步的状态：没开始 / 进行中 / 完成。
- 课这一步里有三小步：**上课 → 测验 → 补漏**。补漏不强制：测验后有漏洞时，下一步按钮是"跑费曼"，旁边可以"进入下一步"。
- "下一步"由宿主按进度算出来，不由 agent 说（见"下一步怎么算"）。
- **手动标完成**（2026-11-05 用户定要）：agent 忘了报告时，你可以在方向主页把一步（课这一步可以单标某一小步）标成完成，也能撤回。手动标的记 `"by": "manual"`，测验分数留空；之后 agent 再报告同一步，以 agent 的为准。

### 常驻步骤条（原型 C，2026-11-05 用户选）

- 方向主页和这个方向的每个学习会话，标签栏下面都有一条步骤条：当前级的名字、每一步一个小方点（课是方点，后面几步是圆点；做完的、当前的、没做的颜色不同）、当前这一步和小步的说明、下一步按钮（加一个次要按钮）。
- 它代替了早先设计里输入框上方的"学习胶囊"。
- 讨论中（还没有阶梯）：步骤条只写"讨论中，排出阶梯以后这里显示当前一级的步骤"。

### 方向主页

方向主页是标签栏最左边固定的一个标签（学士帽 + 方向名），关不掉，会话标签开在它右边，标签前的图标表示用途。主页内容（原型 C）：

- 标题、当前级、一句话定档（目标 · 语言 · 每周时间）。
- 当前步骤卡：第几步、做什么、上课/测验/补漏三小步、开始按钮。
- 这一级的全部步骤：做过的步骤下面挂着它的会话（上课、测验 + 分数、费曼），点开就是那个会话。
- 右栏：阶梯（各级的名字，跳过的、当前的、没到的）、漏洞（来自哪一题，已补的划掉）、其他会话（讨论、随口问）、档案（目录里的文件，点开用现有的文件预览）。

### 会话的用途

| 用途 | 怎么开 | 做什么 | 写回 |
|---|---|---|---|
| 讨论 | 新建方向时；在方向主页的会话列表里点开 | 定档、摸底、排阶梯 | 名字、阶梯、起点那一级的步骤、资料、定档 |
| 排计划 | 升级时由宿主开场；没开成或没排完时，步骤条的"排计划"/"回到排计划" | 按阶梯和剩下的漏洞排下一级的课：先列出来问你"准备这样排，确认吗？"，你确认后才写，写完两三句话收尾、停下；可以在 `resources.md` 追加这一级的资料，不改阶梯、不改 `AGENTS.md` | 这一级的课（记录 `{ kind: "plan", level: 新的一级 }`） |
| 上课 | 课这一步的"开始上课" | 讲一点、在 `lab/` 里动手一点、看你的代码；必要时放演示 | 笔记；这一步"上课完成" |
| 测验 | 上课完成后的"开始测验"；"以后再测"的一步上的"补测" | **上课会话的子对话，带上下文**（SPEC-0002 用户开的子对话，宿主以 `--fork <上课的会话文件>` 起，见"ML3 定的细节"）；一次一题，选择题用提问卡片，答完立刻判、补讲 | 分数、漏洞 |
| 费曼 | 有漏洞时步骤条的"跑费曼"；主页漏洞行的"跑费曼"（带过来的漏洞只能从这里开） | 新会话（不是测验的子对话），针对一个漏洞：先讲简单版，你讲回去，讲不清就补；讲不清就不标 | 漏洞标为已补；一份讲解笔记（记录的 `level` 是开的时候的当前一级，漏洞来自这一级时 `step` 是来源那一步，来自之前几级时不写 `step`，`gap` 是漏洞） |
| 速查表 | 速查表这一步 | 把这一级压成一页 | `cheatsheet.md` 里加这一级 |
| 过关项目 | 过关项目这一步 | 在 `lab/` 里做，按过关标志验收 | 这一步完成 |
| 综合测验 | 综合测验这一步 | 整级内容，10 题由浅到深 | 分数、漏洞 |
| 随口问 | 主页标签栏的"+" | 普通会话，带方向的上下文 | 不改进度 |

- 开一个有用途的会话时，宿主发隐藏命令 `/atrium-study <用途> <base64url JSON>`（同 ADR-0013 的做法，`/atrium-` 只有宿主能发），扩展把它展开成给模型的提示。消息气泡由界面显示成"上课 · 第 2 级第 4 步"之类，宿主不产出给用户看的文字。
- 一件事一个会话（2026-11-05 定），会话之间靠档案衔接：每个会话开始时 agent 读方向的进度、上一节的笔记、没补的漏洞。
- 各用途展开后的提示词**先照推文的 6 段提示词写**（讨论用"排阶梯"和"挑资料"，上课用"20 小时"，测验用"考到出错"，速查表用"速查表"，费曼用"费曼"），用起来再慢慢调（2026-11-05 用户定）。

### 下一步怎么算

宿主按进度决定步骤条上的按钮，agent 只负责报告"做完了什么"：

| 当前这一步 | 情况 | 主按钮 | 次要按钮 |
|---|---|---|---|
| 课 | 还没上 | 开始上课 | — |
| 课 | 上课完成、没测 | 开始测验 | 以后再测 |
| 课 | 测完、这一步有没补的漏洞 | 跑费曼 | 进入下一步 |
| 课 | 测完、没有漏洞，或漏洞都补了 | 进入下一步 | — |
| 速查表 / 过关项目 / 综合测验 | 没做 | 生成速查表 / 开始项目 / 开始测验 | — |
| 升级 | 前面的都完成、综合测验那一步有没补的漏洞 | 跑费曼 | 升级 |
| 升级 | 前面的都完成、综合测验没有没补的漏洞 | 升级 | — |
| （这一级没有课） | 升级后还没排出这一级的课 | 排计划（已有这一级的排计划会话时是"回到这个会话"） | — |

正在跑的会话里，按钮是"回到这个会话"，不重复开。

### 升级

- 升级是步骤条的最后一步，点了弹确认（原型第 13 屏）：升到第几级"名字"；"把这一级的 N 个会话一起归档"默认勾上，可以取消（档案和笔记都留着，会话能在"已归档"里恢复）；没补的漏洞带到下一级。
- 确定后开一个"排计划"会话，排下一级的步骤。下一级到这时才排，用得上前面学下来的情况。
- 升级做的几件事、顺序、失败时怎样，见"ML3 定的细节 · 升级"。
- 最后一级过关后，方向标"已学完"，还能随口问、复习。

### 方向目录

```
~/Atrium/Learning/<目录名>/
├── .atrium-study.json   标记 + 进度（见"接口与数据"），只经扩展工具改
├── AGENTS.md            方法论规则；pi 每个会话都读，agent 不改
├── resources.md         挑的资料和使用顺序
├── cheatsheet.md        每一级一节
├── notes/               每节课一篇，费曼的讲解
├── visuals/             演示（SPEC-0007）
└── lab/                 练习代码，自己的 git 仓库
```

- **pi 读 AGENTS.md 不需要信任目录**（pi 1.5.0 源码核实，`resource-loader.js` 的 `loadProjectContextFiles`：从工作目录一路往上找 `AGENTS.md`、`CLAUDE.md`，和信任无关；`.pi/prompts`、`.pi/skills`、`.pi/SYSTEM.md` 才要信任）。所以方法论放 AGENTS.md，命令由 Atrium 扩展注册，不放 `.pi/prompts`，方向目录不用信任。注意上层目录（`~/Atrium/`、`~`）的 AGENTS.md 也会被读到。
- AGENTS.md 由宿主建方向时写入方法论规则（英文，给模型看；你可以改，agent 不改，2026-11-09 改：原先讨论时 agent 在后面补定档，定档现在只在 `.atrium-study.json`）。规则包括：一次只讲一点、让学生动手、测验一次一题、不替学生写 `lab/` 里的代码、按内容挑展示形式（原型"展示形式"第 6 屏）、每个会话开始先读进度和漏洞。

### 演示

用 SPEC-0007，目录是 `visuals/`，文件名 `<级>-<步>-<名字>.html`。学习模式在 AGENTS.md 里多两条：每节课最多一个演示；最多加一个让学生先猜的问题，猜的结果作为一条"来自演示"的消息回到会话里。方向主页的档案里列出演示，笔记里可以链过去。

### 联网

讨论时挑资料、上课时查新版本的用法，用 pi 里默认装好的联网工具，也就是 Atrium 扩展自带的 `web_search`、`web_fetch`（ADR-0014，2026-11-05 用户定）；不另装别的搜索。没有配置搜索的 key 时，agent 只凭自己的知识挑资料，并在 `resources.md` 里注明没有联网核对。

```jsonc
  },
  "gaps": [
    { "id": "g1", "text": "分不清可重复读和串行化各挡住了什么", "from": { "level": "l2", "step": "s3", "question": 4 }, "fixedAt": null }
  ],
  "finishedAt": null

```

- 文件由宿主建、由扩展工具改（下面），agent 不用编辑工具直接改它。宿主读的时候校验，读不出的按"讨论中"显示，并提示文件坏了，不覆盖。
- 读文件时保留不认识的字段（同 domain-model"格式版本"）。

### 扩展工具（只有学习会话有）

| 工具 | 谁用 | 作用 |
|---|---|---|
| `study_set_name` | 讨论 | 改显示名 |
| `study_set_profile` | 讨论 | 写定档 |
| `study_set_ladder` | 讨论 | 写阶梯、起点（哪些级跳过）和起点那一级的课，一次写完；写了讨论就算结束（2026-11-09 改：原先起点那一级的步骤另用 `study_set_steps` 写） |
| `study_set_steps` | 排计划 | 写当前这一级的课（还没排过时）；只能写这个排计划会话记录的那一级，那一级不是当前一级时拒绝（ML3） |
| `study_report` | 上课、测验、费曼、速查表、过关项目、综合测验 | 报告这个会话做完了什么：上课完成、测验分数、过关项目验收通过…… |

- 每个工具只在对应用途的会话里有（同 SPEC-0002"哪些会话有哪些工具"的做法）。
- 工具说明写清楚什么时候调；agent 不调，进度就不动，你可以在主页上手动标完成（协议 `study.mark`，见"一级 = 一串步骤"）。
- `study_set_ladder` 的级数不在 2～6 之间时拒绝，错误码 `study.ladder_size`（协议里写作 `study_ladder_size`），参数带 `min`、`max`、`got`。

### 索引

- `sessions.json` 的会话记录多一个可选的 `study: { kind, level?, step?, gap? }`（新增可选字段，不升版本）。
- 方向的别名、置顶、上次打开时间存在新的 `learning.json`（同 `chats.json` 的结构）；归档不记在这里，看目录在不在 `Archive/` 下。

### ML2 定的细节（2026-11-09）

实现 ML2 时定下、上面没写到的（2026-11-09 用户全部同意；视觉按原型 `study-progress-states-prototype.html` 选的 1A、2D、3A、4A、5A，写在 design-language"学习模式"）：

**用途怎么交给模型**

- 宿主给方向里有用途的会话（讨论、排计划、上课、测验、费曼、速查表、过关项目、综合测验）起 pi 时加 `--atrium-study=<base64url JSON>`（`{ v: 1, kind, level?, step?, gap? }`，写法同 `--atrium-agent`）；随口问、没有用途的会话（`study: null`）和方向外的会话（工作区、对话）都不加。
- 扩展只在有这个参数时注册 `study_*` 工具，并且只注册这个用途用得到的（2026-11-09 用户强调：普通会话的工具表里根本没有学习工具，不只是用 `--exclude-tools` 去掉）。pi 在扩展加载之后才设参数，所以扩展在 `session_start` 里读参数、注册工具。宿主照样按调用方会话的记录核对用途（第二层），不对的回 `study_not_allowed`。
- 每次运行前扩展按用途在系统提示里加一段 `atrium_study`（先照推文的 6 段写）；pi 重启后照样有。讨论的第一条消息是你自己发的普通消息，不经隐藏命令。
- 宿主开的会话（ML2 是上课、速查表、过关项目、综合测验；ML3 加上测验、费曼、排计划）建好后，宿主确认 `get_commands` 里有 `atrium-study`，再发隐藏命令 `/atrium-study start <base64url JSON>`（`{ v: 1 }`，只有版本，用途和第几级第几步扩展从启动参数读）。扩展发一条 `atrium-agent` 自定义消息开一轮（`details` 是 `{ v: 1, kind: "study", deliveries: [], study }`），内容是给模型的开场；对话记录里这一轮的来源是 `{ kind: "study", study }`，界面画成"上课 · 第 2 级第 4 步"的气泡，宿主不产出文字。

**工具（按用途给）**

| 用途 | 工具 |
|---|---|
| 讨论 | `study_set_name`、`study_set_profile`、`study_set_ladder` |
| 排计划 | `study_set_steps` |
| 上课、速查表、过关项目 | `study_report` |
| 测验、综合测验 | `study_report`、`study_add_gap` |
| 费曼 | `study_fix_gap` |
| 随口问、没有用途 | 没有 |

- 工具经 ADR-0013 的通道问宿主（`atrium-agent:` 状态，`op` 就是工具名）。宿主核对用途，校验参数，排队写文件，答结果或错误码。
- `study_report`、`study_add_gap` 写的是调用方会话记录里的那一级那一步，参数里不带级和步，写不到别的步骤上：上课报"上课完成"（不带分数）；测验、综合测验报分数 `{ score, of }`（`0 ≤ score ≤ of`，`1 ≤ of ≤ 100`）；速查表、过关项目报"完成"。`study_fix_gap` 只能标费曼会话记录里那一个漏洞。
- 阶梯写过以后再调 `study_set_ladder` 回 `study_ladder_set`（第一版不改阶梯）；当前这一级已经有课时 `study_set_steps` 回 `study_steps_set`。

**`.atrium-study.json`（v1）**

```jsonc
{
  "version": 1, "name": "Node 后端", "createdAt": "…",
  "profile": { "goal": "…", "weeklyHours": "4-8", "language": "TypeScript" },   // 都可以没有，每段最多 200 字
  "ladder": [ { "id": "l1", "name": "…", "topics": "…", "pass": "…", "state": "skipped" | "current" | "done" | "todo" } ],
  "steps": { "l2": [
    { "id": "s1", "kind": "lesson", "title": "关系建模",
      "lesson": null | { "by": "agent" | "manual" },
      "quiz": null | { "by": "agent", "score": 42, "of": 50 } | { "by": "manual" } | { "by": "later" },
      "done": null | { "by": "agent" | "manual" } },
    { "id": "s10", "kind": "sheet" | "project" | "exam" | "up", "done": null | { "by": "agent" | "manual", "score"?: 8, "of"?: 10 } }
  ] },
  "gaps": [ { "id": "g1", "text": "…", "from": { "level": "l2", "step": "s3", "question": 4 }, "fixed": null | { "by": "agent" | "manual" } } ],
  "finishedAt": null

```

- id 由宿主给（`l1`…、`s1`…、`g1`…）。agent 只给课的题目（每级 1～30 节）；速查表、过关项目、综合测验、升级这 4 步由宿主接在课后面，没有题目，名字由界面按种类写。
- 上限：级名 60 字、学什么和过关标志各 500 字、课题目 120 字、漏洞 1000 字、显示名 256 字，"字"都按看到的字符（字形簇，同 ML1 起名的规则）数，扩展、通道、档案的读写和协议用同一个函数（2026-11-09 用户定）；超了工具回 `agent_text_too_long`（带字段和上限）。这些上限不写进工具的 JSON Schema（`maxLength`）：写了 pi 会在扩展之前按自己的说法拒绝，模型拿不到字段和上限（ADR-0013 第 9 条），由扩展自己查（2026-11-09 评审后改）。漏洞最多 200 条，满了 `study_add_gap` 回 `study_gaps_full`（带 `max`）。
- 整份档案写出来不能超过 1 MiB（读的上限），超了不写，回 `study_file_too_large`（2026-11-09 评审后加）。
- 读的时候严格：哪一处形状不对、级数不在 2～6，整份按"坏了"算：方向显示"讨论中"、标出文件坏了，工具回 `study_file_broken`，不写。`version` 比 1 大的照样读认识的部分，不写（`study_file_version`）：方向列表里标 `newer`，步骤条和主页照样显示进度，但没有按钮、没有手动标记，`start_study_session` 也回 `study_file_version`（2026-11-09 评审后定）。
- 不认识的字段在每一层都保留（顶层、每一级、每一步、每个漏洞）。
- 写：同一个方向的写排队一个一个来；每次写之前先确认方向目录仍是学习目录下一层的真目录（`lstat` 不是链接、`realpath` 的上一层就是学习目录），不是就不写（`learning_dir_unsafe`，工具回 `study_write_failed`）；再重新读文件，在同一个目录新建临时文件（从建出来起归这次写，之后哪一步失败都删掉）再改名换上，标记文件是链接的不写（`O_NOFOLLOW`）。写完宿主重新扫描，界面跟着变。
- 归档方向时先等这个方向排在前面的写做完再移目录；归档开始以后来的写都拒绝（命令回 `direction_archived`，工具回 `study_not_allowed`），`Archive/` 里不会留下临时文件。开有用途的会话和归档、恢复按方向一个一个来，开之前在队里再算一次下一步，同时按两下只开一个会话（2026-11-09 评审后定）。
- 讨论结束的判断：有阶梯（`study_set_ladder` 一次写出阶梯和起点那一级的课）。起点是第一个不跳过的级；全部跳过的拒绝（`agent_bad_request`）。

**下一步（宿主算，规则表补充）**

- 当前这一步是当前一级里第一个 `done` 为空的步骤。课这一步：`lesson` 空 → 开始上课；上过、`quiz` 空 → 开始测验，次要"以后再测"；测过（agent 或手动）且这一步有没补的漏洞 → 跑费曼，次要"进入下一步"；测过、没有没补的漏洞 → 进入下一步。
- "以后再测"：这一步记 `quiz: { by: "later" }`、`done: { by: "manual" }`，往下走；主页在这一步上显示"没测"，悬停可"补测"（原型 4A）。
- "进入下一步"：这一步记 `done: { by: "manual" }`，没补的漏洞照样留着。
- "回到这个会话"：方向里有没归档的会话，记录的用途、级、步和主按钮要开的一样（不论在不在跑），主按钮就是打开它（最近活动的那个）。
- ML2 里能开的会话只有上课、速查表、过关项目、综合测验；测验、跑费曼、升级的按钮画出来但不能点（"即将开放"，原型 2D），ML3 接上（见"ML3 定的细节"）。
- 归档的方向、已学完的方向、档案读不出来的方向、档案版本比 1 大的方向都没有按钮（原型 2D）；这几种方向的主页也没有手动标记和撤回。已学完的方向没有当前一级，步骤条和主页显示最后一级的步骤，点全亮。

**手动标完成**

- 只能标还没完成的，只能撤回手动标的；agent 报告的不能撤回。之后 agent 报告同一项，以 agent 的为准（`by` 换成 `agent`、写上分数）。
- 升级这一步不能手动标（只有升级本身能完成它，ML3）；速查表、过关项目、综合测验只能"标为完成"。
- 撤回"整步标为完成"时，它当时一起手动标上的上课、测验也撤回，回到标之前的样子；之后 agent 报告过的（`by: "agent"`）留着（2026-11-09 用户定）。整步的标记里记下它一起标了哪几项（`done: { by: "manual", parts: ["lesson", "quiz"] }`，读时可以没有）。
- 课这一步能单标"上课""测验"或整步；标测验时上课一起标上（手动），整步是上课、测验（空的那几项）和完成都标上。撤回一项时，它后面手动标的也一起撤回。agent 报告测验时，上课也一起记成 agent 的。
- 补漏不在步骤上标：在漏洞上"标为已补"（`fixed: { by: "manual" }`，原型 3A），能撤回；之后费曼标同一个漏洞以它为准。
- 协议：`mark_study_step { directionId, level, step, mark: "lesson" | "quiz" | "step" | "later", done }`、`mark_study_gap { directionId, gapId, fixed }`；不合规则的（已经完成、撤回 agent 的、不是课却标小步）回 `study_mark_refused`，找不到级、步、漏洞回 `study_not_found`。

**协议的其他部分**

**费曼和补测从哪开**

- 宿主算一个"现在能开的"集合（StudyRules，纯函数，和下一步一起算）：
  1. 主按钮要开的那个（含"排计划"）；
  2. 每个没补的漏洞的费曼（不论来自哪一级）；

**升级**

- 命令 `upgrade_study { directionId, level, archiveSessions }`，应答 `{ planSessionId: string | null, notArchived: number }`。带 `level` 是为了两个窗口各点一次时只升一级。在方向的队里做（同开会话、归档方向），顺序：
  1. 在队里再算一次下一步：方向归档了回 `direction_archived`；档案读不出来、版本更高回 `study_file_broken`、`study_file_version`；`level` 不是当前一级，或者升级这一步不是当前步骤（主、次按钮里都没有升级）回 `study_not_available`。
  2. 写档案（这一下就是"升级"本身，原子写，同 ML2 的写法）：这一级的升级一步记 `done: { by: "manual" }`（升级是你点的；这一步本来就不能经 `mark_study_step` 标或撤回），这一级 `state: "done"`，后面第一个 `todo` 的级变成 `current`（跳过的不动）；后面没有 `todo` 的级（最后一级）时写 `finishedAt`。写失败回写档案的错误码（同 `mark_study_step`），什么都不动。
  3. 勾了 `archiveSessions` 时归档这一级的会话（见下）：一个失败不挡其他的，同一棵子对话树里也是（子对话归档失败，后面的照样归档，归档成的照样从布局里去掉），`notArchived` 是没归档成的会话个数（子对话也一个一个算），升级照样算成。
  4. 不是最后一级时，开这一级的排计划会话（`study: { kind: "plan", level: 新的一级 }`）、宿主开场，界面把它作为当前标签打开；这一级已经有没归档的排计划会话（手改过档案又升一次）时不开第二个，打开那个（同"同一个（用途、级、步、漏洞）只开一个会话"），`planSessionId` 就是它；开不成时 `planSessionId` 是 `null`，下一步的规则会给"排计划"，从步骤条接着来。最后一级不开排计划，方向是"已学完"。
- 当前一级还没有课（`steps` 里没有这一级的课步骤：没有这一级、是空的，或者手改得只剩速查表这几步）时，下一步是"排计划"（`start`，用途 `plan`、级是当前一级、没有步）；已有这一级没归档的排计划会话时是"回到这个会话"。排计划没开成、开了没排完（agent 没调 `study_set_steps`），都这样接上。这时步骤条和主页的样子：步骤条照 2A（新的一级、没有点阵、"还没排课"或"排计划中"），主页照 6A（"排计划"卡、步骤列表是虚线占位）。
- 这时 `study_set_steps` 把课写在这一级最前面：这一级原来一步都没有时照常接上速查表、过关项目、综合测验、升级 4 步；手改得还剩几步时留着它们（id 不重用，课的 id 接着往后编（2026-11-10 用户定：照此））。
- 步骤条、当前步骤卡、步骤列表里升级这一步的名字：后面还有没到的级（跳过的不算）时是"升到第 N 级"（N 是后面第一个没跳过的级，同确认框和宿主），没有了是"学完最后一级"，步骤条上写"学完"；这一级已经学完了（看之前几级时）也按这一条，跳过的不算（2026-11-09 评审后定：原先写的是紧挨着的下一级，跳过的级也算）。
- 已学完的方向显示最后学完的那一级（`done` 的最后一个），不是阶梯上排在最后、可能是跳过的那一级。
- 已学完的方向没有手动标记和撤回（"ML2 定的细节"）：界面不画步骤的"···"菜单、漏洞的勾和"撤回"，宿主的 `mark_study_step`、`mark_study_gap` 也回 `study_mark_refused`（2026-11-09 评审后加：原先只是界面不给）。
