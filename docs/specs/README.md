# 需求与技术方案

每份 spec 描述一个功能或改动：要解决什么问题、怎么做、怎么验证。写在动手之前，评审后实施。

## 规则

- **一事一文**，新建时复制 [template.md](template.md)，编号取下一个。
- 方案里影响长远的取舍，单独写成 [ADR](../adr/) 并互相链接。
- 实施完成后，把稳定的设计沉淀到 [architecture](../architecture/)，spec 本身保留为历史记录。

## 状态

| 状态 | 含义 |
|---|---|
| 草稿 | 编写中 |
| 评审中 | 等待讨论和确认 |
| 已确认 | 可以开始实施 |
| 实施中 | 正在开发 |
| 已完成 | 已实施并验证 |
| 已放弃 | 不再推进，注明原因 |
