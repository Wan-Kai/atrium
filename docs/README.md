# Atrium 文档

## 目录

| 目录 | 放什么 | 特点 |
|---|---|---|
| [`architecture/`](architecture/) | 架构设计：系统整体结构、核心模型 | 活文档，始终描述**当前**设计，随实现持续更新 |
| [`specs/`](specs/) | 需求与技术方案：单个功能或改动的方案 | 一事一文，有状态流转，实施后基本不再改 |
| [`adr/`](adr/) | 架构决策记录（ADR）：一个重要决策及其理由 | 只追加不修改，被推翻时写新 ADR 取代旧的 |
| [`research/`](research/) | 调研与学习笔记：外部项目分析、学习资料 | 参考性质，不约束实现 |
| [`roadmap.md`](roadmap.md) | 路线图 | 阶段计划与原则 |

## 三类核心文档的关系

```
        一个新需求
            │
            ▼
  specs/NNNN-xxx.md  ── 方案中的关键取舍 ──▶  adr/NNNN-xxx.md
            │
            │ 实施完成，稳定的部分沉淀
            ▼
  architecture/*.md（更新当前设计）
```

- **spec 回答"这件事怎么做"**：写在动手之前，评审后实施。
- **ADR 回答"为什么选这条路"**：只记录影响长远、难以撤回的决策。一份 spec 可以产生零到多个 ADR。
- **architecture 回答"系统现在长什么样"**：读者不需要翻历史就能看懂当前设计。

## 约定

- **命名**：`specs/` 和 `adr/` 下的文件用四位编号加英文短横线命名，如 `0001-pi-rpc-adapter.md`。编号只增不复用。
- **语言**：正文用中文，代码、标识符、文件名用英文。
- **状态**：spec 和 ADR 开头写明状态，取值见各自目录的 README。
- **模板**：新建时复制对应目录下的 `template.md`。
- **链接**：文档之间用相对路径互相引用，决策依据链到 ADR，不在多处重复论证。
