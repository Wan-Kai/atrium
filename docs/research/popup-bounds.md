# 桌面弹窗边界排查

本次属于 M1.11 自用后的修复，涉及 SPEC-0002“显示 · 子对话条”和 SPEC-0001 的菜单、模型面板、状态栏与对话框。用户要求同时排查其他弹窗，不能只补子对话列表。

## 已复现

使用真实 `ChildCapsule` 和项目测试客户端，仅在临时页面提供 24 条子对话。960 × 783 的视口里，列表高 1046.5px，底部 597px，顶部 −449.5px；计算样式 `max-height: none`、`overflow-y: visible`，设置 `scrollTop` 后仍为 0。3 条时高 164.5px、顶部 432.5px，未越界。

原因：`CapsuleUnit` 固定把面板放在胶囊上方 8px，只测横向空间；`ChildCapsule` 没有补高度与滚动约束。排队面板虽然有 `46vh` 上限，但它不是锚点上方的实际剩余空间，输入框和提问卡片变高时仍需验证。

在临时页面中按上方实际剩余空间限高并设置内部滚动，顶部回到 12px，`scrollTop` 能到 400px。此探针不改生产代码，不等于修复完成。

## 本次范围

- 通用菜单的全部调用方：侧栏、标签栏、面包屑、子对话操作、工作区和设置选择器等。
- 模型与推理强度面板、输入框附件菜单、命令与文件候选。
- 状态栏详情卡片与自定义面板、Fast 说明、服务商名称提示、改名提示。
- 开子对话与归档确认对话框、设置窗口和归档提示；已有全屏图片预览检查现有边界回归。

只修边界、内容可达和必要的浮层层级，不改主题、文案、业务行为、宿主或协议，不改原生系统对话框。

## 已选交互

原型：`prototypes/popup-bounds-prototype.html`，用户已选 A“原位限高”。默认尺寸与位置沿用现有设计：子对话、排队、模型等面板保持原来的展开方向，按实际空间限高并滚动；普通短菜单不足时换到能放下的一侧；居中对话框限制在窗口内，长内容滚动。B 对所有锚点面板也自动换边；C 把长列表变成居中对话框。

先同步 SPEC 和 design-language，再写失败回归与实现。验证应断言实际矩形在可用区域内、首尾项可滚动触达、打开时新增内容与缩放窗口会重算、嵌套操作菜单不被父滚动区裁剪，并保留关闭、焦点和减弱动态效果行为。

## 实现边界

`design/floating-layer.ts` 统一负责锚点几何、窗口安全边界与浮层生命周期，不负责打开/关闭、内容、焦点策略或业务操作。用 Chromium/Electron 已有的 manual popover top layer 逃出祖先裁剪；DOM 仍留在原位置，保留父面板 `contains()` 的外点判断、事件传播与样式继承。相比 portal，无需给每个父面板建立跨树归属；相比单纯 fixed，不受 filter/transform/overflow 祖先影响。不开自动 light-dismiss，不增加依赖。

各组件继续拥有展开状态、既有理想宽度和内容滚动方式。公共定位在窗口四边留 12px；按锚点与指定方向计算实际余量，面板不换边，短菜单/非交互说明可换边；原有更小的高度上限继续有效。窗口缩放、滚动、锚点和祖先尺寸变化、浮层内容变化时重算，卸载释放观察和监听。居中对话框直接用 CSS 限宽限高及长字符串换行，不纳入锚点定位模块。

兼容性边界是桌面 Electron 44 / Chromium 152；不新增宿主、持久化或协议。新增 top-layer 行为用滚动父容器、嵌套菜单、关闭/Escape、焦点、明暗外观与监听回收的真实 Chromium 回归守住。

审查补上模态暂停、no-drag、悬停浮层按需观测、原尺寸与滚动保持；归档提示同样用几何模块，普通浮层之上、模态之下，只有超高时裁剪滚动，正常阴影/入退场和空隙穿透保持。真实滚轮发现的“量尺寸时临时放大导致滚回去”也已用原生 scroll 事件后两帧的回归锁住。
