# M1.11 自用记录

M1.11 用开发模式（`pnpm dev`，数据在真实的 `~/.atrium`）连续一周完成真实的编码任务，这里记下过程和结论（[路线图 · M1.11](../roadmap.md#m111-自用)、[SPEC-0001 · 验证](../specs/0001-mvp1-single-session-chat.md#验证)）。开始于 2026-10-11。

## 每天做什么

1. 用 Atrium 做当天的编码任务，每个会话记一行到"会话"。
2. 收工前跑 `pnpm usage`，看最近几次运行：
   - 带 `↑` 的行说明最后一个小时的最低值比第一个小时高（资源计数变高，或内存涨到 1.5 倍以上），可能有泄漏；
   - 运行不到两小时的不比较，只看每小时的数值有没有一路往上走。
   发现持续上涨就记到"问题"，补一个能复现的泄漏测试再修（[testing.md · 运行时监控](../architecture/testing.md#运行时监控)）。
3. 碰到 pi 不如 Codex 的地方，记到"pi 和 Codex 的差距"；碰到 Atrium 自己的问题，记到"问题"。出错时用界面上报的 trace id 跑 `pnpm trace <trace id>` 看链路。

## 新账户首次启动

M1.10 完成标准第一条：在一个没装 pi 的 macOS 账户上，从首次启动走到第一次对话。

1. 系统设置里新建一个标准用户，登录进去；确认 `which pi`、`which node` 都找不到，`~/.pi` 不存在。
2. 把仓库拷到这个账户下（或用共享目录），`pnpm install` 后 `pnpm dev`。
3. 依次走欢迎页、装 pi（没有 Node 时先装 Node）、登录、添加项目，记下每一屏是否顺畅、出错时显示了什么。
4. 新建会话，发一条消息，确认有回复。
5. 退出再打开，确认不再显示首次启动。
