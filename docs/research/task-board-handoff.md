## 一、背景与我们要解决的核心问题

我们需要在 Atrium 中设计一个类似「任务看板 / 任务台」的界面，统一管理用户的：
1. **定时任务（Scheduled / Cron Routines）**（如：每晚 02:00 全量变异测试、每日生产日志 `pnpm errors` 与资源 `pnpm usage` 巡检、iOS 免费签名 7 天到期检查等）
2. **零碎任务（Quick / Ad-hoc Tasks）**（随手记的小修小补、单点优化）
3. **复杂 Agent 任务（Feature / Spec Tasks）**（遵循 Atrium 标准开发流程的多阶段任务）

**核心痛点**：
传统的看板（`Todo → In Progress → Review → Done`）无法很好地处理一个 Agent 任务。因为一个 Agent 任务在 Atrium 里本质上是一个 **「有向图（DAG）+ 状态机（State Machine）」**，需要管理**如何设计、如何运转、如何验收**，并且在运行中途如果图结构要发生变化，必须找用户确认。

## 二、用户已拍板的 4 条铁律（设计必须 100% 严格遵守）

1. **铁律 1：每个任务下发后都必须先放到「待我介入」环节**
   - 用户可以随时下发任务（零碎任务、复杂 Agent 任务、或定时任务触发出的提案）。
   - **任何新下发的任务，第一步都先进入「待我介入」区域**（例如生成初始执行图 `v1` 后停在启动确认门禁），经用户确认拍板后，才正式建 worktree / 起进程往后跑，绝不擅自黑盒开跑。
2. **铁律 2：「待我介入」有单独、醒目的操作区域**
   - 把所有阻塞等待人类决策的任务单独抽离到独立操作区，按要用户做的决策类型区分：
     - **① 新任务初始图确认**（刚下发的任务，确认初始节点图后启动）
     - **② 设计 / 方案拍板**（做好了调研或 HTML 原型，等用户选方案 A/B/C 或回答 `ask_user`）
     - **③ 运行中动态改图确认（Graph Diff Gate）**（Agent 运行中途发现原计划走不通，申请新增/拆分节点或改依赖边，等用户批改图）
     - **④ 最终验收合并**（跑完实现、破坏检查与三方审查，看 Diff 与验证清单，一键合并回 `main` 并清理 worktree，或带一句备注打回某节点重跑）
3. **铁律 3：任务列表保持极简，不强行塞微缩图，点开之后再打开详情**
   - **不要**在任务列表的每一行里画拥挤的微缩流程图或节点轨道！
   - 列表里每一行只干净、克制地展示 **3 个核心字段**：
     1. **当前在哪个节点**（例如：`N2 · 核心实现与自检` 或 `N3 · 三方并行审查 (2/3)`）
     2. **运行了多久**（例如：`14m 28s`，使用 `tabular-nums` 等宽数字）
     3. **是否被阻塞了**（例如：`⏸ 已阻塞 · 等你确认改图` / `⏸ 已阻塞 · 等你确认初始图` / `◌ 运转中 · 无阻塞`）
   - **只有点击列表中的某个任务（或待我介入卡片）后，才打开详情视图查看它的完整图与状态机**。
4. **铁律 4：任务执行逻辑是「图 + 状态机」，运行过程中如果图要变，必须找用户确认**
   - 点开的任务详情里，展示完整的 **有向图（DAG）+ 节点状态机**：
     - **节点（Node）**：映射到主会话的阶段或 `agent_spawn` 的子对话（`explore` / `work` / `advise`）。每个节点有明确状态机：`pending`（待上游）→ `running`（运转中）→ `blocked_on_human`（阻塞等你） / `passed`（通过） / `failed`（失败触发回退或升级） / `proposed`（申请新增或修改待确认）。
     - **有向边（Edge）**：支持顺序流转边、并行分叉与汇合边（Fan-out / Join，如同时派出 Astra + Grok + Claude 三个只读审查子代理，全过才解锁验收）、以及失败/打回的回退边（Rollback Edge）。
   - **运行中动态改图确认（Graph Diff Gate）**：
     - 当 Agent 在执行某节点时发现原图不够用（如需要把 `N2` 拆成 `N2a + N2b`，或动态插入一个 `N-Leak 泄漏回归` 节点），任务立即进入阻塞态并浮上「待我介入」。
     - 在详情的图画布上，直观展示 **Graph Diff**（原图实线，拟新增/拆分/移除的节点与边用高辨识度虚线高亮 `+ 拟新增节点` / `~ 拟拆分`，并展示改图原因、文字 Diff 摘要及版本号 `graphVersion: v1 → v2 待确认`）。
     - 用户可点击 **「批准改图（升至 v2 并继续）」** 或 **「拒绝改图（维持 v1 原图继续）」**（可附一句备注写进节点证据链）。

## 四、原型设计要求与执行步骤

请在 `prototypes/agent-task-board-prototype.html` 中完成高完成度、可真实交互的单文件 HTML 原型：

1. **提供 3 种可一键切换的布局方案（底部切换栏 A / B / C + 深浅色切换）**：
   - **方案 A（推荐）：主界面为「顶部下发与定时条 + ⚡ 待我介入独立操作区 + 极简任务列表（当前节点/运行时间/是否阻塞）」，点击任意任务从右侧滑出宽敞的「图 + 状态机 + 改图 Diff 详情抽屉」**。
   - **方案 B：原地推入全屏详情（Drill-down）**——平时主界面只看「待我介入 + 极简任务列表」；点开某个任务后，主区切换为沉浸式的全屏 **DAG 图状态机工作台**（左上角一键返回任务列表）。
   - **方案 C：主从双栏（Master-Detail）**——左侧固定为紧凑的「待我介入 + 极简任务列表」，右侧常驻当前选中任务的 **DAG 图状态机画布与节点检查器**。
2. **必须包含的真实交互演示**：
   - **下发新任务**：在输入框输入任务（可选：零碎任务 / Agent 特性 / ⏱ 定时任务）并提交 → **立刻出现在「⚡ 待我介入」专区**，状态为 `⏸ 阻塞 · 新任务等你确认初始图`，点确认后才变为 `◌ 运转中` 并开始计时。
   - **定时任务（Cron Routines）交互**：展示日常定时规则（无异常静默归档），支持点击「模拟定时触发异常」→ 自动派生一张任务卡进入「⚡ 待我介入」等你确认修复图。
   - **点击任务查看「图 + 状态机」详情**：
     - 清晰的 SVG 有向图（包含已完成节点、运行中节点、阻塞节点、并行子代理分支 `↳ review-astra` / `↳ review-grok`、回退边）。
     - 点击图上的任意节点，下方联动显示该节点的**状态机流转轨**、绑定的会话/子代理、耗时与产出证据。
   - **运行中动态改图确认（Graph Diff Gate）**：
     - 默认有一张处于「✦ 申请动态改图 (`v1 → v2`)」的任务卡，并支持在任意运行中任务上点击「模拟运行中触发改图申请」；
     - 在图画布上对比展示原图节点与虚线高亮的 `+ 拟新增节点` / `~ 拟拆分边` 及改图原因，点击「批准改图」后虚线转实线、版本号升为 `v2` 并继续运转；点击「拒绝改图」则移除提案节点按原图继续。
3. **防止连接中断的写入建议**：
   - 写大 HTML 文件时，建议分阶段写入或分段 `Edit`（例如先写 `<style>` 与骨架，再写 `<script>` 数据与交互渲染），避免单次输出超过 1500 行导致流式连接中断。
4. **完成后打开浏览器预览**：
   - 写完并校验 HTML 结构完整后，执行：
     ```bash
     open prototypes/agent-task-board-prototype.html
     ```
