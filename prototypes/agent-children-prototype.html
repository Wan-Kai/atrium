原型 · agent 开子对话（SPEC-0002 第二步）

主对话的 agent 用 agent_spawn 开了两个子对话：安全审查（只读，同一工作区）和 补测试（可写，新 worktree agent/tests），再用 agent_wait 等齐汇总。问题一点"下一步"走一遍：汇报进度 → 补测试问主 agent、等待提前返回、回答后接着等 → 都做完、合回、汇总。

默认 agent 不等（开完就结束这一轮），子对话做完后由通知开一轮新的：那时的"合回"就是问题二里新一轮的开头，不在原来那一轮的轨道上。

要定的：问题一过程轨道的分出和合回，选 A / B / C；问题二通知开头的轮，选 甲 / 乙 / 丙；问题三只有一种，看有没有要改的。

问题一 · 过程轨道：分出与合回

  • A 车道：每个在跑的子对话一条自己的竖线（x = 22.5、33.5），和主线并行往下；做完时从右边弯回主线，空心节点写"名字 完成 · 用时"。最像 git 图，一眼看出几个在并行；车道多了文字往右挪。
  • B 分出卡片：分出处向右弯出一张小卡片，名字、角色、实时状态和最近一条进度都在卡片里，点卡片打开；做完另起一行，空心节点从右边汇回（同插话的画法）。信息最全，占地方。
  • C 普通步骤：和读文件、跑命令一样是一行，右边的结果原地从"运行中"变成"✓ 完成"；进度写在第二行。不画分支和合回，结果在下一轮的开头看。最安静，但看不出"分出去了"。

问题二 · 由通知开头的轮

  • 左边是主对话（收到"来自子对话「安全审查」完成"、中途插进来的"补测试 在问"），右边是子对话（第一件事"来自主对话的 agent"）。给模型的外壳文字（<atrium-agent-report …>）不显示。
  • 甲 来源行：没有气泡，一行小字说来源和事件，右边"打开"；子对话里交代的事用引用块。
  • 乙 来源气泡：靠左的气泡（和你的消息左右分开），头上写来源，正文是回复的前三行，"展开"看全文。
  • 丙 细线：同"上下文已压缩"那种居中细线写来源，下面直接是这一轮。

问题三 · 排队面板、子对话条（一种方案）

  • 排队面板里待送达的是另一种项：图标 + "来自子对话「补测试」：完成"；还没发的能删（×），"已交给 pi"的删不掉。不能编辑、不能改成插话。
  • 子对话条的行：agent 开的多一个角色小标签（只读不写字，"可写""顾问"写字）、"在问主 agent"的状态（问号，橙色，和"待回答"同形但写法不同）、第二行最近一条进度。
  • 宿主重启后待送达的都暂停：列表顶上一条"重启后暂停了 2 条送达 · 全部继续"，一次恢复整棵子树。
