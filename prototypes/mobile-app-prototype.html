Atrium 手机 App · 视觉方向

A 系统原生

iOS 26 Liquid Glass 的导航栏与 tab bar、inset grouped 列表、系统 sheet。Atrium 的颜色只用在状态和强调上。

适合：想要"像系统自带 App 一样"顺手、少学习成本；三个 tab（会话 / 改动 / 主机）把看进度和看改动分开。

代价：和桌面不像一个产品，过程轨道退化成普通列表行，Atrium 的点阵、小猫、层级色几乎看不到；"等你处理"只是列表里的一组，信息密度低（大标题、44pt 行），一屏放的会话最少。

SwiftUI：最省事。NavigationStack + List(.insetGrouped) + TabView（iOS 26 自带 Liquid Glass 的 tab bar、toolbar、.sheet 的 detent）+ Menu / Picker / Toggle 全是系统控件；提问用 .sheet(presentationDetents: [.medium, .large])。

B Atrium 延续

沿用桌面的层级色、0.5px 细线、22px 气泡、过程轨道、点阵和运行中的小猫，导航自绘。

适合：手机和桌面是同一个产品：侧栏的"项目 → 工作区 → 会话"、收件箱卡片、过程轨道、提问卡片、改动树、点阵模型按钮都照搬，桌面上定过的规则（排队 / 插话、序号即控件、空状态那句话）手机上不用重新解释。

代价：自绘导航，要自己做返回手势、动态字体、VoiceOver 的细节；侧栏式的三层树在手机上偏挤，"等你处理"卡片在底部，会话多时要滚到底才看到；提问卡片和输入框叠在一起，题多时占掉半屏。

SwiftUI：中等。轨道用 Canvas 或 Path + 叠放的 HStack；点阵、涡旋用 Canvas + TimelineView；底部输入区 safeAreaInset(edge: .bottom)；返回仍可用 NavigationStack，隐藏系统栏再画自己的标题行（保留边缘右滑返回）。

首页是按紧急度排的卡片流：等你处理在最上，运行中其次，已完成未读最后。对话以全屏 sheet 打开，提问在卡片上直接答。
