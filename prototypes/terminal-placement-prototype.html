内置终端放在哪：三种放法

同一份内容在三种位置上的样子。终端块在浅色界面里也是深色（design-language 的 --term）。 场景都是真实形状：一个工作区标签、一个对话标签，右边是文件/更改栏。

A 独立标签

宽度够，Claude Code / Codex 这类 TUI 能按 100+ 列排版。
代价：看终端时离开对话，切回来要来回点标签。

B 右栏第三页

不离开对话，和"文件""更改"并排，顺手。
宽度只有 340px（约 44 列），TUI 会挤成一团，只适合看日志。

C 对话下分屏

边看对话边敲，高度可拖，dev server 日志和 agent 输出能对照看。
代价：跟对话滚动区抢高度；多个终端要靠内部标签区分。

  1. 入口：对话输入框上方一个"终端"按钮，或者标签栏 + 里"在对话下开终端"。默认高度约 40%。

  6. 风险：长对话本来就靠滚动，多一条常驻分屏会让对话更窄；要不要记住"这条对话上次开着终端"需要定。
